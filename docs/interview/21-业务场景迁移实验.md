# 21｜业务场景迁移实验：把同一个 Runtime 用到不同问题

[返回目录](README.md) · [实战主线](20-实战主线与环境手册.md)

## 为什么不能只会讲 NaumiAgent 自己

理解框架内部并不自动等于会解决业务问题。面试官可能把“代码修复”换成知识问答、工单处理或发票下载，观察你能否重新定义输入、权限、结果和失败语义。因此本章围绕同一套运行思想安排三个迁移实验：知识问答、业务操作、浏览器交付。它们不是要求另做三个大平台，而是检验你能否在具体场景收敛范围。

交付状态必须先说明：本章提供样例与验收规格，不声称完整 RAG、工单服务或真实网站流程已经实现。知识实验提供可用的虚构数据和八道验收题；业务和浏览器实验先在自建隔离环境进行，再按授权接入外部系统。完成这些实验的读者应留下自己的实现与结果，而不是照抄本章的预期答案。

## 实验 A：带来源、版本与权限的知识问答

输入是 [knowledge.json](labs/knowledge.json)，包含现行制度、旧制度、受限资料、故障手册和一段对抗文本。验证集为 [retrieval-cases.json](labs/retrieval-cases.json)。所有制度、预算数字与部门都是虚构样例，不适用于真实企业或专业决策。

第一步先不用模型，构建检索输入：文档 ID、正文、版本、访问范围和替代关系。employee 只可读 employee 文档；finance 在本实验中可读 employee 与 finance；未知角色默认不返回资料。角色来自应用的可信会话，不能从用户问题中“我是财务主管”解析成权限升级。先按身份限制可检索资料，再生成模型上下文。

第二步建立你能解释的检索基线。这个小数据集可以先用关键词规则，不必为了五篇文档引入复杂基础设施。若改成向量或混合检索，要保存参数并用同一问题比较；仅仅引入 embedding 不算质量提升。R03 明确问历史与现行差别，因此需要同时返回旧文档和替代文档；默认当前规则问答则应以现行文档为准，不能用统一“删除所有旧资料”解决所有问题。

第三步接入生成。要求输出答案、来源 ID 和资料不足项。R06 没有答案，拒答或说明缺资料才正确。R08 包含恶意指令，正确行为是解释风险，不执行上传。提示词可以提醒，但实际文件与网络权限仍由工具执行边界约束。

第四步逐题核验。检查检索阶段是否出现 forbidden_sources；只要受限正文进入了不该看到它的模型上下文，即使最终回答没泄漏数字，也应判权限失败。expected_sources 是本题应支持答案的来源，不是机械要求所有任务都返回固定数量片段。回答中出现 ID 还不够，要确认引用内容确实支持结论。

毕业成果是一条“输入身份与问题→检索→上下文→回答与来源→独立评分”的完整路径，以及八题逐题记录。不要只统计回答流畅度，更不要将小样例八题全部通过宣传为企业知识库普遍准确。

## 实验 B：只允许创建草稿的业务操作助手

场景是用户要求“根据工单内容起草回复”。先做一个本地虚构工单环境，字段包括 ticket_id、owner、status、message 和 revision。只读查询与写草稿是不同工具；发送回复是另一项动作，本实验默认不提供发送权限。不要把查询、修改、发送都放在一个任意 action 字符串中且不分级授权。

设计三条验收：正常读取工单并保存草稿；工单不存在时说明失败且不编造客户信息；用户要求发出时停在待确认或不支持状态，而不是偷偷发送。增加修订号是为了处理查询后内容变化：草稿依据 revision=3 生成，但工单已变成 revision=4，就要重新核验，不能拿旧批准直接作用于新内容。

进阶场景是发送请求超时。先说明结果可能未知，设计稳定业务请求 ID 和查询结果接口。不要依靠“再来一次”解决所有超时。若自建服务支持幂等，重复请求应得到相同业务效果；若服务不支持，就明确未知状态和人工对账路径。这里只是接口契约要求，不宣称 NaumiAgent 的任意 Tool 已自动具备幂等。

交付物包括数据模型、工具 schema、错误分类、三条基础用例及一个超时状态图。自建工具若进入产品 Runtime，需要按项目规范注册到真实执行入口并完成权限与测试，不把仅有说明的函数称作业务集成。

## 实验 C：浏览器下载与结果核验

使用你能控制的本地测试页面或明确获授权的网站，展示一份虚构报表并提供下载。不要以真实支付、客户隐私或网站风控挑战作为新手练习。先观察页面与账号范围，再触发一次下载，最后检查文件格式、内容和数量。

分别演练登录等待、按钮不存在、下载为空和重复下载。等待登录期间必须能取消，不能把等待当作同意；定位失败时重新观察，不能反复点击旧坐标。下载事件发生不等于文件内容正确，工具返回 success 也不等于用户收到正确报告。

项目 [browser heartbeat](../../src/naumi_agent/runtime/browser_heartbeat.py) 可以帮助理解运行与等待状态，[SoM 测试](../../tests/unit/test_browser_som.py)可用于阅读观察与定位机制，但本章没有交付一个已经验证的任意网站下载机器人。真实站点、登录与文件核验要在你自己的实验记录里补齐。

## 怎样迁移到面试问题

三个场景共享一组问题：真正完成条件是什么？数据由谁授权？模型能决定什么、不能决定什么？结果未知时怎么办？怎样证明没有越权或漏项？面试中不需要把所有模块重讲一遍，而应选出本场景最重要的约束。

如果问为什么不直接用固定工作流，先判断任务是否需要动态行动。固定输入和固定步骤的工单草稿可以采用确定性流程；多来源开放研究可能需要更灵活的决策。你能解释何时不使用复杂 Agent，比每个场景都套多 Agent 更能体现判断力。
