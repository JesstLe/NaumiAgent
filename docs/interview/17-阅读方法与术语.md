## 先修知识：不要求先会训练模型，但要读懂程序怎样运行

本教材默认你能阅读基础 Python：函数、类、异常、列表和字典。第 02、07、13 章涉及 async/await：等待模型或网络返回时可以让其他任务执行，但“并发”不等于 CPU 同时计算，也不保证共享状态安全。理解 JSON 和 HTTP 请求/响应，才能看懂工具参数与远程调用；理解 SQL、事务和唯一约束，才能判断任务写入为何冲突。pytest 的断言用于检查预期行为，mock 是替身，不是真实模型或远端服务。

遇到不懂的基础概念时，先缩小到一个函数和一个测试，不要在 engine 的长文件中从第一行硬读到最后一行。也不要先收集几十个框架名称：能解释一次失败为何发生、哪些状态被保存，才有工程理解的起点。本书重点是应用与运行时工程，不替代算法、模型训练或推理服务专项课程。

## 六组容易混淆的词

| 术语 | 用初学者能理解的话解释 | 最常见的误解 |
| --- | --- | --- |
| LLM / Agent / Workflow | LLM 是模型；Agent 围绕目标选择动作并利用反馈；Workflow 组织流程，里面也可以包含 Agent。 | 以为多轮聊天自然具备可靠执行能力。 |
| Runtime / 状态机 | Runtime 是让程序实际运行的管理层；状态机规定当前阶段允许哪些迁移。 | 以为必须使用一个巨型 StateMachine 类。 |
| Prompt / Context / Token | Prompt 常指给模型的指令；Context 是本次调用实际带入的信息；Token 是模型处理文本等输入的计量单位。 | 把 token 数当作固定中文字数，或以为模型自动看得到磁盘文件。 |
| Memory / RAG / Ledger | Memory 保存可复用信息；RAG 检索资料辅助生成；Ledger 精确记录任务或操作事实。 | 用语义相似的旧聊天判断订单是否已提交。 |
| Tool / MCP / Skill / Hook | Tool 执行动作；MCP 规范能力通信；Skill 包装任务说明与可选资源；Hook 在生命周期事件处触发逻辑。 | 以为安装 Skill 就新增了已授权 API，或 Hook 可以绕开权限。 |
| Trace / Eval / Harness | Trace 记录发生的事件；Eval 用任务和判分方法衡量效果；Harness 的含义取决于是运行支撑还是评测支撑。 | 以为日志完整就代表任务正确。 |

这些词可以组合，但不应互相替代。例如，一个 Skill 可以告诉 Agent 按模板检查代码；Agent 调用本地 Tool 读取文件，或通过 MCP 调用远端工具；Hook 可以在特定事件触发检查；Runtime 负责决定如何处理结果。哪一步真的运行了代码、哪一步只是提供说明，需要沿实现查看。

## 恢复与安全词汇，不用死记英文

幂等（idempotency）表示同一业务请求重复处理时，不产生额外的业务效果。不是重复返回同一句“成功”，而是不能重复创建订单或发送同一消息。幂等键必须稳定绑定业务请求；每次重试都生成新键通常不能达到去重目的。

Lease 是有期限的执行权；Heartbeat 是执行者报告存活或状态的信号；Fence 是在提交边界拒绝过期执行者。Epoch 可理解为递增的任期编号：新执行者属于新任期，旧任期不应覆盖新结果。这些机制只有在具体校验边界才有效，并不能隔空撤回已经发往外部系统的请求。

Checkpoint 是检查点，即保存下来的运行状态；Replay 是按记录重放。恢复时还要确认工具副作用是否已经发生。重放若再次发送真实邮件，就不是安全的只读重现，所以要区分记录回放与重新执行。

Authentication 是认证，回答“你是谁”；Authorization 是授权，回答“你能做什么”；Sandbox 是对进程、文件、网络等资源的隔离。Guardrail 通常指某类输入、输出或动作检查，具体能力要看实现。授权批准不是模型输出中的一个单词，而应由可信执行路径验证。

Fail closed 是检查失败时默认不放行；Fail open 是检查不可用时仍允许继续。两者在可用性与风险上有取舍。第 06 章的对账函数读取异常后返回 NONE 加 warning，不能直接称作默认拒绝。还需要看上层如何处理警告。

## 建议的四轮学习路线

需要从第一条命令开始的读者，先打开[实战主线与环境手册](20-实战主线与环境手册.md)，运行[离线机制实验](labs/README.md)，再按下面四轮补齐理解。这样可以边运行边读源码，不必先背完所有概念。

第一轮建立闭环：读 01、02、04、07，用“生成周报草稿”解释目标、上下文、工具反馈和终止。验收是不看目录也能画出任务循环，知道用户没授权发送时不能发送。

第二轮看事实与边界：补 03、05、06、08。运行一个 Goal 或 Todo 测试，区别配置、计划、持久记录与权限。验收是能解释“任务勾选完成”和“真实结果完成”为何不同，能指出模型档位只是配置映射而不是质量保证。

第三轮处理失败：读 09、10、12。挑一个超时、等待或租约案例，看失败如何传播到用户结果。验收是能回答“远端已经成功，本地却超时，重试会怎样”，并明确真实站点演练和 mock 测试的差别。

第四轮扩展与面试：读 11、13、14、15、16。设计一个小范围改进，写出输入输出、风险、评测与回滚条件。验收是能说明何时不需要 MCP、多 Agent 或自我演进，不以架构复杂度代替效果。

不规定几天学完；基础、可用环境和实验范围差别很大。每章读懂一个真实案例再前进，比每天扫过所有标题更有价值。

## 怎样阅读源码和测试

从章节提供的关键符号开始，用编辑器查找定义和调用者。先写下输入类型、返回类型、持久化位置和异常路径，再读测试断言。看到 mock 路由器，就标记“未调用真实模型”；看到临时 SQLite 或文件目录，可以说真实执行了本地存储逻辑，但不能说经过生产流量验证。

文中命令在仓库根目录运行，依赖项目开发环境。环境缺失时先参考[项目 README](../../README.md)与[依赖定义](../../pyproject.toml)，不要为了运行教材而覆盖已有配置或安装到全局环境。测试命令是帮助定位机制，不是要求在生产目录启动未知外部动作。

每次实验保存六项信息：版本、输入、执行命令、实际结果、预期结果、证据范围。测试失败时先看具体 assertion 和错误输出，区分依赖未安装、环境不支持、测试期望漂移、真实逻辑回归。不能看到红字就猜根因，也不能改掉断言后声称功能正确。

## 面试自测与诚实表达

用五个问题复习每章：没有这个模块会怎样？它读什么并改变什么？为什么不用更简单的方案？失败后留下什么状态？你拿什么证据证明结论？能回答这五点，再练习教材中的示范题。

评分时把“概念准确、机制清楚、源码对应、失败意识、证据边界”各记 1 分。低于 4 分先回看案例，不急着背术语。真正的项目经历要补入你的决策与实验：为什么选这个改动，排除了什么假设，哪些条件下结果会失效。

本书是模拟面试训练，不保证某个公司的题频或录用结果。准备国内大厂面试时，仍要根据具体职位说明补齐语言、数据库、网络和系统设计基础；涉及训练或推理优化的岗位还应另做对应实验。
