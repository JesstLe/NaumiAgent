- 全片每 10 秒取一帧，共 49 张；按段读取原尺寸关键画面，并在结尾补取 07:55、07:57、07:59。
- 时间戳是画面在录屏中的位置，不把画面中的历史聊天时间当成实时执行时间。
- 音轨 mean/max 均为 -91.0 dB，接近静音；本次以画面和可读文字核对，不声称听到了语音演示。
- 画面有持久Agent、双方对话、报告Page、单次Routine实体等；长久记忆、外部发布读回、语音和电脑操作并未全链路展示。
- 原视频与截图保留在本地附件/忽略的事务目录，未提交含个人账户信息的原始画面。

## 产品定位的修订

2026-11-05 术语对齐：每个对象都是独立 Agent，研究、运营等仅是可调整分工。下方带时间戳的视频观察保留原始描述，不代表 NaumiAgent 预置职业或替用户命名。

初始只有一个个人主 Agent，用户明确要求后才动态创建常驻Agent或团队；名称、领域和数量均不预设。
用户可统一委托，也可直接找Agent；Agent之间传递有来源的材料，过程能打开查看，
最后回到用户可使用的真实产物。独立 Agent 不是一个 prompt 里扮演的多个名字。

视频中的“团队”目前能确认的是角色入口与协作行为，并未证明每个团队下面还有多个 worker。
NaumiAgent 的 Team 因此要明确成员关系和真实 Run，不根据命名虚构组织层级。

## 核心接力示例

用户已创建的 Agent 分别承担机会研究 → 草稿起草 → 领域/事实复核，主 Agent 检查并汇总。
这条链保留“不发布”、篇幅要求、上游来源和未核验状态；用户不再手动转发上下文。
视频 07:55 展示总控指出数值问题，说明目标包括复核，不只是汇总。

## 实施顺序与首次可验收里程碑

完整模块定义见[产品方向](README.md)。本次新增 PA-00、PA-06～PA-11，旧编号保留。

1. **PA-00 常驻Agent**：身份/配置/会话/目录，创建后可真实对话与调用工具，重启保留。

3. **PA-07 研究复核与 PA-08 产物工作台**：分别实现、分别验收，不将文本质量与富界面混成一个半成品。

5. **PA-03/PA-09 连接与外部行动**：先一个真实账户/渠道，从读取到审批、写入和读回。

第一个产品里程碑不是“侧栏出现几个头像”，而是：用户创建三个Agent，
由主 Agent 派发真实研究，承担起草的 Agent 引用研究产物写草稿，承担复核的 Agent 发现预置错误，
总控交付修订后的报告与草稿，用户可查看每次交接，重启后团队和成果仍存在。
该里程碑跨多个模块，应逐个交付；未经用户批准不把草稿发布到外部账户。
