## Agent 身份与命名（2026-11-04 用户修正）

每个持久对象都是独立的 Agent，不是固定职业的人员。研究、运营、内容、投资等只是可以调整的能力或本次分工，不构成预置角色类型。初始只有主 Agent；其余 Agent 和团队仍仅按用户明确要求创建。名称由用户决定，不默认追加“员”或“专员”，不因任务类型替用户重命名已有 Agent。职责、模型、工具和协作关系可以变化，身份与历史保持连续。

Tool/OpenAPI 的兼容类型、当前产品文档和身份连续性回归已同步，见[Agent 身份与分工](../../development/personal-agent/agent-identity.md)。

[工具权限接缝](../../development/personal-agent/permission-contracts.md)；账户真实验收仍独立记录。

## 1. 已确认的产品范围

用户希望 NaumiAgent 成为 Personal Agent，并明确同时覆盖：

1. **个人执行助理**：持续跟进个人事项、按约定触发行动、交付结果。
2. **个人工作助理**：代码、文档、调研、资料整理和项目推进。
3. **个人生活助理**：日程、邮件、资讯、学习和日常安排。

这不是三个独立助手，也不是把编程 Agent 的名称改成个人助理。
三个领域共享个人档案、事项、执行记录和结果收件箱；工作区变为上下文之一，
不再是产品顶层身份。工作与生活的具体数据仍保持明确的作用范围。

**产品定义：一个认识用户、掌握相关上下文、能够接受委托并持续完成工作与生活事务的个人 Agent。**

## 2. 用户价值与边界

### 理解我

- 能记住明确偏好、长期目标、常用资料位置和已确认的工作方式。
- 分清用户原话、外部材料、助手建议和待确认推断，不能把自己的建议记成用户要求。
- 每条重要记忆有来源、范围、更新时间和状态；用户可以查看、纠正、删除、导出。
- 工作区资料不自动变成全局个人记忆；“个人 / 项目 / 单次任务”必须明确隔离。

### 替我做事

- 用户交代事项后，得到真实事项 ID、执行状态、需要确认的动作和结果位置。
- 工作：读取指定文件、调研、写文档、生成代码和验证产物。
- 生活：处理日程与待办、准备邮件草稿、整理学习材料及信息；逐个接入真实服务。
- 持续执行：依据时间或已连接事件触发、跨会话继续、失败后恢复或请求用户决策。
- 整理材料等已授权动作可自动执行；发送、购买、删除、发布等外部变更采用具体授权规则，
  绑定账户、对象、动作、有效期和额度，并提供清楚的待确认入口与撤销授权能力。

### 主动但不打扰

- 主动来源是用户委托、已确认规则或已连接事件，不是无依据地自行扩展目标。
- 汇总低优先级消息，尊重勿扰时间，只在需要决策、完成交付或重要失败时通知。
- 桌面前台关闭不应丢失事项；后台服务退出、设备休眠或关机后的执行语义要明确。
- 本机关闭时不承诺仍能执行。持续在线能力需要实际常驻设备或后续云端执行器。

## 3. 当前源码事实

以下仅为本轮只读源码核对，不代表这些能力已通过新的运行态验收。

### 可以复用的基础

- `src/naumi_agent/personal/memories.py` 与 `memory_store.py`：owner-bound SQLite 记忆、来源、确认、范围、确切分享与擦除。旧 `memory/long_term.py` 只作显式 legacy 导入来源。
- `src/naumi_agent/orchestrator/goal_store.py`：SQLite 目标状态和事务转换。
- `src/naumi_agent/daemons/agent_jobs.py`：持久执行、租约、fencing、终态、结果 inbox 与交付回执。
- `src/naumi_agent/runs/`：Run 记录、恢复、公开活动和工具证据。
- `src/naumi_agent/scheduler/`：once/cron、持久事件、暂停/恢复/取消。
- `src/naumi_agent/tools/` 与 `mcp/client.py`：文件、浏览器、工具和 MCP 桥接。
- `frontend/web2/`、桌面壳与 CLI/TUI：现有交互入口；不再另造一套执行引擎。

### 四个核心协调点

1. **个人档案**：PA-02 已接通 owner/actor 与个人/工作区/事项范围、来源和人工确认、冲突、
   修订、删除及实际模型发送前的当前授权解析。旧全局 Chroma 不再自动召回；
   完整设备同步、发布安装及真实平台保留策略仍按各模块单独验收。
2. **个人事项**：`GoalStore` 保持每工作区一个未结束目标；现有 session Task 偏执行协作。
   个人同时推进多项工作和生活事务，不宜直接放宽执行层不变量来充当事项系统。
3. **主动执行与送达**：`ScheduleTarget` 已在 PA-01 增加独立的 `personal_item`；
   `collect_notifications()` 取出事件即标记 delivered，engine 在交互循环中注入通知。
   PA-01 已区分到期、受理、执行、站内投递与人工已读；设备通知与周期规则仍按后续模块验收。
4. **个人账户连接**：PA-03 已接通 Google 主日历的 OAuth、加密凭据、授权续期、

   真实账户读写和远端撤销仍待独立验收，邮箱及其他平台保持各自未完成状态。

## 4. 建议的共享架构

```text
个人入口：桌面 / Web / CLI-TUI / 后续移动入口
                    ↓
个人上下文：用户档案、分范围记忆、工作区与已连接服务
                    ↓
个人事项：目标、截止时间、优先级、重复规则、授权策略
                    ↓
触发与编排：时间 / 服务事件 / 用户继续 / 有界主动建议
                    ↓
已有执行底座：Goal / AgentJob / Run / Tools / MCP
                    ↓
结果与送达：产物、依据、执行回执、通知状态、用户确认
```

### 数据职责

- **Person / Profile**：个人身份与显式偏好；凭据引用不混入向量记忆。
- **PersonalAgent / Team**：持久Agent身份、职责版本、会话、资料与记忆范围、工具和账户绑定。
  它与临时 subagent / 单次 worker 分开，不能把仅存在于一次运行的角色当成常驻助理。
- **Delegation / AgentMessage**：委派、上下文与产物引用、发送/接收/结果回执，
  绑定真实 agent_id、parent_run_id、任务与权限范围，支持打开原始交接记录。
- **Memory**：带来源、范围、状态和修订记录的事实与偏好。
- **PersonalItem**：长期委托，包含工作/生活领域、截止时间、优先级、状态及策略。
- **Trigger**：时间与时区、事件订阅、去重键、错过触发策略。
- **Run**：一次实际执行；复用已有运行态 ID、取消、恢复和证据，不创建第二套执行状态机。
- **Artifact / Delivery**：结果文件与送达记录；生成成功、送达成功和已读分别记录。
- **Connection**：账户、能力、授权引用、同步游标和健康状态。

一个事项可以产生多次 Run；任务已触发不等于已完成，报告已生成不等于用户已经收到。
执行结果不明时保留 UNKNOWN，不为填满完成列表而自动重复外部变更。

## 5. 建议的产品界面

继续采用浅色布局和已确认的黑白 N 品牌，避免解释性标语。

主导航建议保持五项，另设常驻“我的 Agent”目录，支持选择主 Agent或Agent，
不把Agent头像仅作为同一聊天角色扮演的装饰：

1. **今日**：需要用户处理的确认、今天的事项、已完成交付。
2. **对话**：交代任务、补充上下文和讨论结果。
3. **事项**：工作/生活/学习分类，进行中、等待、到期与周期事项。
4. **记忆**：用户资料、偏好、事实与来源；提供纠正和删除。
5. **连接**：文件位置、邮箱、日历及其他真实账户的状态。

工具、模型、日志、评测和自进化进入设置或开发者视图，不把内部能力名称当作普通用户主导航。
首模块先接入现有界面的真实事项入口，数据链通过后再逐步迁移导航，避免静态空壳首页。
