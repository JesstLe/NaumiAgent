# Web2 具体执行摘要（2026-09-11）

## 分阶段公开摘要与组件组合（2026-09-11）

- 后端新增 `phase_summary` Runtime 事件。引擎在一轮真实工具调用全部得到结果并写入
  tool message 后发布事件，事件携带实际 `turn`；每项仅包含经过公开动作投影的
  `action` 与机械 `status`，不读取、传输或持久化模型隐藏 reasoning。
- `progress_summary()` 根据上述事实生成中文阶段摘要，例如
  `本阶段已完成：读取文件：README.md。`；失败、停止、多于三项和重复动作均有
  有界规则。该摘要通过 SSE 的 `activity_summary` 发送，并由现有两条 run recorder
  路径保存为 `activity` step，因此刷新和历史回放后仍存在。
- Web2 按 ReAct `turn` 形成阶段。每阶段先显示现有 Beautiful UI Thinking 外壳及
  Tool Chips，再用现有 `MessageContent` 显示透明背景的公开摘要；下一轮工具出现在
  下一段 Thinking 中，最终回答仍位于所有阶段之后。
- 组件按真实内容选择：计划与上下文压缩使用 Steps，普通公开进度使用 Reasoning，
  浏览器与网页工具使用 Search，其余工具使用 Coding + Tool Chips。Search 没有
  合法 URL 时显示普通行，不生成空链接；官网查询和 `+7 more` 示例不会进入产品。
- 旧 run 没有 `phase_summary` 时，前端仅根据已经保存的 `public_action` 与工具终态
  生成兼容摘要。该回退不补造验收结论，也不会读取旧 `analysis.detail`。
- 当前阶段摘要是执行事实摘要，不是模型自由撰写的思维过程。它能说明计划在工作目录
  执行什么、读取或修改了什么、是否查看页面布局、是否压缩上下文及结果状态；产品是否
  修复仍由工具证据、测试和最终答复共同确认。
- 本轮验证通过：Python 事件、传输、持久化及引擎工具发布定向测试 115 项，前端映射
  单测 16 项，TypeScript、生产构建和 5 项浏览器场景通过；另 2 项需要显式真实会话
  环境变量的 Playwright 场景按设计跳过。生产构建仍有既有主包体积提示。
- 当前 `openai/kimi-for-coding` 真实会话形成 5 个 turn：读取入口文档、执行命令、
  搜索文件、读取被引用文档和最终整理。每轮工具之后出现独立公开摘要，最终回答位于
  全部阶段之后；页面刷新后仍恢复 5 个阶段与 4 条工具阶段摘要，摘要计算背景均为透明。

## 问题

原执行过程仅有两句固定文案。TOOL_START 的公开传输丢弃所有参数，且页面
没有保留上下文压缩和任务快照事件，无法说明具体操作。历史回放还会优先展示
analysis.detail，不适合作为公开摘要来源。

## 实现

- 新增公共动作摘要构建器，只读取工具名称及有限的路径、命令、目标字段。
  不读取模型思考内容，不展示编辑正文、浏览器脚本或完整参数 JSON；敏感值脱敏，
  访问地址省略凭证、查询和片段，摘要有长度上限。
- 工具启动附带 activity_summary；持久化使用 metadata.public_action，结束事件
  保留原动作。引擎与 HTTP 两条记录路径复用相同生成规则。
- 任务快照与上下文压缩转换为公开进度行并持久化；压缩统计使用消息条数，
  不误标为 token 数。任务仅显示实际任务状态，未知操作保留名称。
- Web2 展示本次请求与工作目录、操作摘要与执行状态、上一步结果状态以及
  任务和压缩进展。历史记录从操作证据恢复，不读取 analysis.detail。
- 每个持久化 run 绑定到对应的用户消息，并在该轮助手回复之前渲染。切换到
  下一轮、向上滚动或刷新页面后，旧轮次的执行过程仍保留在原位置；旧记录中
  message id 未关联时，按请求摘要和时间顺序恢复对应关系。
- 不收集 thinking_delta，避免无可见信息的高频事件挤掉实际工具记录。
