# Web2 归档 404 修复（2026-09-11）

## 原因与处理

Web2 调用 `POST /api/v1/sessions/{id}/archive`。首次检查时 8765 服务的
OpenAPI 不包含该路由，虽然当前源码已实现，因此这是运行中后端与源码不同步
造成的路由 404。用户随后授权并完成后端重启；当前实际 OpenAPI 已包含归档
路由，5174 通过同源代理调用当前 8765 服务。

共享 API 客户端将归档接口缺失与会话不存在分别提示：前者要求更新并重启
后端，后者要求刷新会话列表。409 执行中冲突保留服务端中文原因；失败不重试，
不把 404 当作归档成功。Web2 继续使用共享控制器移除列表项并清空当前选择。

## 验证

- 前端 Vitest：44 项通过；包括真实路径、空 204 响应、旧服务 404、会话缺失
  404 和执行中 409，确认每次操作只发送一次请求。
- Python 归档 API、SessionStore、SessionPort：31 项通过。新增用例使用真实
  引擎、SQLite 与完整应用路由，检查执行中拒绝、重复归档、重新打开数据库、
  消息完整保留和其他会话隔离。
- `ruff check src/ tests/integration/test_api_session_archive.py` 通过；
  TypeScript 与 Vite 生产构建通过，仍有原有大 chunk 提示。
- 实际通过 Web2 的 5174 → 8765 代理创建专用验收会话 `931eac7193be`，
  归档返回 204；再次归档返回 204；重新读取列表不再出现该会话，直接读取
  状态为 archived，原始内容仍在，其他会话均保留。证据位于
  `.naumi/data/archive-verification.json`。

## 自审与边界

当前问题已在实际代理和后端链路消除。后续联合浏览器回归已覆盖 Web2 页面、
归档路由、刷新恢复和错误提示；对应的前端、Python 与 Playwright 定向测试均通过。
历史全量 `pytest tests/ -x -q` 的失败记录不据此改写为全量通过，验收结论仍以
本模块及后续联合回归记录为准。
开发时更新后端路由后仍需重启服务；单独刷新 Web2 页面不会加载 Python 新代码。
