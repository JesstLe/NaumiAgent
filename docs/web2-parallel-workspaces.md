# Web2 并行工作区与运行中导航

## 问题

Web2 过去把一次消息执行的 `busy` 状态当成整个窗口的锁。任务推理期间，创建项目、选择目录和多处页面操作会被禁用。桌面壳同时只保存一个全局 daemon；如果只移除禁用状态，切换目录会先停止这个 daemon，正在执行的任务也会随之终止。

## 实现

- 当前窗口推理期间仍可切换会话、查看设置、文件、Diff、插件和其他只读页面。
- 当前窗口空闲时，项目切换仍在原窗口完成。
- 当前窗口推理时，新建对话、创建项目或打开其他目录会创建辅助窗口。
- 每个 Tauri 窗口按窗口 label 持有独立 daemon，并从 `8765-8799` 中分配独立端口。
- 窗口关闭时只停止该窗口对应的 daemon，不影响其他窗口。
- 辅助窗口通过 `naumiWindow` 隔离 API、会话、草稿、侧栏尺寸等本地偏好；通过启动参数接收自己的 API 地址和初始会话。

## 行为边界

同一窗口仍只执行一个消息任务。需要并行执行时，新建对话或在会话菜单中选择“在新窗口打开”。多个窗口可以在同一目录运行；它们共享项目文件，因此同时编辑同一文件时仍需要用户处理实际文件冲突。

## 验证结果

- `pnpm test:run`：15 个测试文件、81 个测试通过，包含辅助窗口偏好隔离和启动参数回填。
- `pnpm build`：TypeScript 与 Web2 生产构建通过。
- `pnpm tauri build --debug`：Windows 桌面程序、MSI 和 NSIS 安装包构建通过。
- `cargo test daemon::tests --lib`：7 个 daemon 单元测试通过，1 个真实进程测试按设计默认忽略。
- 使用项目现有 Python 环境单独执行真实进程测试：两个 NaumiAgent daemon 分别监听 `8766`、`8767`；停止第一个后第二个仍存活，最终两个进程均完成清理。
- 对调试安装包执行 WebView2 原生验收：调用 `open_workspace_window` 后成功创建 `workspace-*` 窗口，窗口加载 Web2 并显示“新对话 / 置顶摘要”，使用独立 `8766` API；关闭辅助窗口后该端口监听数恢复为 0，主窗口仍保留。
- `git diff --check`：通过。

## 当前限制

多个窗口可以指向同一个真实目录，因此并行任务同时修改同一文件时仍可能产生文件级冲突。当前实现不会静默合并这些冲突；后续若引入 Codex 式 worktree 隔离，可在新建并行任务时为 Git 项目创建独立工作树。
