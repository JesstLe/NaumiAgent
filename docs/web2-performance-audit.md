# Web2 性能与死代码审计

## 审计范围

本轮检查 Web2、Web 入口、共享工作区状态在浏览器渲染阶段的直接调用关系，同时核对 Git 跟踪文件与本地生成目录。没有改动 Agent 执行引擎、模型调用和持久化协议。

## 已修复问题

### 流式输出期间重复注册全局监听器

Web2 的 `resize` 与 `keydown` effect 原先没有依赖数组。消息流每增加一个 token 都会先移除再注册监听器。现在窗口缩放监听器只注册一次，并通过 ref 读取最新分栏状态；快捷键监听器只在对话框开关变化时更新，快捷键内部使用函数式状态更新。

### 自动滚动反复触发布局计算

消息更新原先同步读取 `scrollHeight` 并写入 `scrollTop`。现在通过 `requestAnimationFrame` 合并同一帧中的滚动请求，并在下一次更新或卸载时取消旧任务。用户向上滚动后仍保持原有的停止跟随行为。

### 不完整历史消息导致界面崩溃

部分兼容接口返回的历史消息没有 `id` 或 `metadata`。旧逻辑会把“编辑状态为空”和“消息 id 缺失”误判为同一条正在编辑的消息，随后读取空对象；助手操作状态也直接读取可选的 `metadata.pending`。现在编辑状态使用显式非空判断，缺少 id 的消息使用稳定的渲染回退键且不显示不可执行的编辑按钮，可选元数据通过安全访问读取。

### 思考过程由空变为有内容时违反 Hook 顺序

`ThinkingState` 在没有阶段时提前返回，但实时事件到达后才调用后面的 `useMemo`，会触发 React Hook 顺序错误并中断消息更新。现在所有 Hook 始终按固定顺序执行，空状态只在 Hook 计算完成后返回。

### 会话搜索无结果提示丢失

搜索词同时不匹配项目名和会话时，旧逻辑会先移除整个活动项目，导致项目内部的“没有匹配的会话”永远无法显示。现在活动项目保留空状态，搜索结果有明确反馈。

### 首屏装入全部 Web 界面与富文本依赖

入口原先静态引入 Web2 和旧版 Web，生产构建生成单个 `1,556.02 kB` JavaScript 文件，gzip 为 `466.86 kB`。现在按访问路径加载 Web2 或旧版 Web；Web2 的设置、项目创建、Diff、上下文、依赖、洞察、文件树和富文本渲染器也按使用时加载。

富文本渲染器中的代码高亮与数学公式依赖分别拆分为独立缓存块，最大 JavaScript chunk 从 `1,556.02 kB` 降至 `350.14 kB`，构建不再产生 500 kB chunk 警告。

Web2 空白工作区初次加载的 JavaScript 为入口 `329.31 kB` 加 Web2 `350.14 kB`，合计 `679.45 kB`，比原来的 `1,556.02 kB` 减少约 `56.3%`；gzip 合计从 `466.86 kB` 降至 `205.71 kB`。初始 CSS 从 `177.22 kB` 降至 `140.52 kB`，富文本 CSS 在出现助手消息时再加载。

### 死代码与无引用样式

删除 `TodoPanel` 已无调用者的 `compact` 模式、相关图标依赖和样式。删除旧版摘要布局与旧状态提示遗留的无引用 CSS：`w2-chat-summary`、`w2-summary-heading`、`w2-working`、`w2-legacy-link`。

消息列表筛选改为按原始消息数组缓存，避免同一次渲染中生成新数组后让运行记录映射缓存失效。

## 文件与缓存核对

Git 没有跟踪 `dist`、`coverage`、`test-results`、`__pycache__`、`.pyc`、`.log`、`.tmp`、`.bak`、`.orig` 或 `.rej` 文件。本地存在的 `dist`、测试报告和 Python 缓存均由构建或测试生成，保持在忽略规则内；依赖目录和 Python 虚拟环境不是垃圾文件，不做批量删除。

`frontend/web2/src/beautiful/upstream`、生成样式和 BorderBeam 均有实际组件调用或来源记录，继续保留。`assets/logo.png` 仍被文档、品牌测试与平台图标构建使用，不属于无用资源。

## 验证边界

本轮只运行 Web 前端 TypeScript、生产构建以及 Web2 布局、路由、富文本和项目创建相关的定向浏览器测试，不运行全仓 Python、Rust 或全部前端测试。代码拆分改变资源加载时机，不改变 API、会话状态或执行协议。
