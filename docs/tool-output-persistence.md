# 工具输出在执行结束后保留

2026-09-11。

## 问题与修复

执行期间前端能收到工具内容，结束后读取运行历史时却没有输出。引擎记录器和 HTTP 流式兜底记录器原先只保存 `delegate_task` 的详情，普通工具的成功输出和错误详情被写成空字符串。

- 两种记录路径共同使用 `runs/tool_evidence.py`，保存经过现有安全规则脱敏的工具输出、输入、调用 ID、截断标记及输出归档引用。保留换行；公共记录最多保存 64,000 字符。
- 工具开始、结束事件按调用 ID 合并；数据库合并元数据，结束事件不再覆盖开始事件的输入。同名并发调用分别保存。
- 执行结束时关闭尚未结束的分析与答复步骤；缺少结束事件的工具标为中断，不推定成功。
- Web 与 Web2 使用共同的活动转换函数。工具列表只计入工具／权限步骤，不把用户请求、分析、最终答复计为工具。
- Web2 在运行结束且运行 ID 对应时读取已保存记录。工具详情支持多行、滚动，并区分等待、明确空输出、历史未保存输出和截断预览。无消息但有运行记录时仍显示执行过程。

## 历史恢复

`runs/recovery.py` 在读取接口返回前，从同一会话原始工具消息恢复旧预览，不重写历史数据库。需要请求摘要、工具顺序、唯一调用 ID 和结果一一对应，还必须有已记录调用 ID 或运行回执中的调用证据作为锚点。只接受唯一匹配；缺少证据、重复或不完整记录不恢复。已保存内容及明确空输出保持原样。

真实会话 `e1fe45644bc7` 的运行 `602418a34626` 恢复了 6 条工具输出：`code_execute`、2 次 `web_fetch`、3 次 `web_search`。实时接口返回的详情长度分别为 78、1084、325、1198、1372、1360。浏览器逐项展开后刷新，再次逐项展开均通过，无页面异常；工具计数由混入生命周期步骤的 9 条变为 6 条。本地后端已加载本次修复。

## 验证与自查

- 相关后端测试：`test_tool_output_persistence.py`、`test_chat_runs.py`、`test_api.py` 共 48 项通过；运行记录器相关回执测试 3 项通过。
- 覆盖同名调用交错结束、错误、空输出、脱敏、数据库重开、会话隔离、终态关闭、归档引用及保守恢复。
- 前端单元测试 37 项、完整浏览器测试 25 项通过，生产构建通过。新增浏览器用例验证流式结束及刷新后的输出和多行样式；该自动用例使用受控 SSE，另以上述实际会话作真实数据验证。
- Ruff 检查通过。
- 扩大运行回执测试时，未修改的 Windows 删除路径测试 `test_receipt_builder_fails_rm_postcondition_when_target_remains` 失败：预期 `partial`，实际 `completed`。测试构造未引用的 Windows `rm -rf` 路径，本轮未改动对应判定逻辑；不声称全量 Python 测试通过。

当前限制：引擎事件可能只提供前 2,000 字符及归档引用，因此工具条目保存的是事件实际提供的预览，不保证为长输出全文；界面提示预览。无可靠原始消息或关联证据的旧记录无法恢复。构建已有主 JS chunk 超过 500kB 的提示仍存在。
