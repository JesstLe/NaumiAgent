# Web2 空回复恢复

## 问题

模型可能结束调用但既不返回正文，也不返回工具调用。旧实现会保存空的 assistant 消息，并把运行标记为 `completed`。Web2 会过滤空消息，最终只剩“已完成”的执行状态，看不到答复。

## 实现

- ReAct 流式与非流式路径都把非空用户可见正文作为成功条件。
- 会话加载与每次模型调用前都会清除旧版遗留的空 assistant 消息；带 `tool_calls` 的合法空正文 assistant 会保留，并继续补齐工具结果。
- 第一次空回复会自动重试一次，并发布公开的恢复摘要。
- 长会话第一次空回复时会先强制压缩旧上下文，再重新执行当前任务；压缩结果在 Web2 显示为公开活动摘要。
- 空回复重试提示与 Harness 纠正指令只保留在当前运行上下文，不再污染持久会话历史。
- 第二次仍为空时，不保存空 assistant 消息；运行写入失败的 response step，并返回中文错误。
- SSE API 校验成功终态必须有正文；若引擎已有正文但遗漏 token 事件，API 会补发正文。
- Web2 在零 token 终态后重新读取持久化消息；仍没有新答复时展示可重试错误。
- 已保存为 `completed`、没有 response step 且回执为默认空摘要的历史运行，在 API 展示层按失败记录呈现。

## 动作任务完成门禁

后续真实验收又发现另一条误完成路径：模型返回一段设计方案，但没有调用文件工具，
旧完成门禁仍会因为正文非空而结束任务。当前实现进一步补齐：

- 用确定性规则识别“创建页面、写入文件、修复代码、实现组件”等直接工作区变更请求。
- `.naumi/harness.yaml` 的 `require_change_evidence` 现在会写入每次完成契约，不再只是未使用的配置项。
- 动作任务没有产生相对本轮起点的真实工作区文件变更时，会阻止模型正文并最多自动纠正两次。
- 这条最低门禁位于 `AgentEngine` 核心，不依赖 Harness Profile 是否存在或受信：必须同时看到本轮成功的工作区写入类工具，以及相对本轮起点的新 Git 文件差异。
- `todo_write`、黑板、记忆等内部状态工具不能充当工作区变更证据；写入相同内容等 no-op 操作也不能通过门禁。
- 长会话中的首次“只返回计划”会把旧 assistant 回复从本次重试上下文移除，只保留当前任务与运行时状态，并在 Web2 显示压缩条数。
- 纠正轮只向模型提供真实写入类工具，并设置标准 OpenAI `tool_choice=required`；Kimi 仍作为选定模型，不切换提供商。
- 空回复恢复和动作纠正分别计数；纠正轮出现空回复后，下一轮仍保留写入工具约束，不会立即耗尽动作纠正机会。
- 纠正事件会转换为 Web2 可见的“执行恢复”摘要，说明正在继续实际执行，不展示隐藏推理。
- 两次纠正后仍没有变更证据时，完成声明被阻塞并记录为失败，不能显示“已完成”。

## Web2 过程状态收口

- 同一 Run 内连续、没有工具调用的恢复轮次合并为一个过程阶段，不再生成多个相互冲突的“已完成”标题。
- “本次任务”只在首轮过程摘要中出现一次；后续轮次使用“继续处理本次任务”。
- 中间阶段统一显示“阶段已记录”；只有 Run 的真实终态为 `completed` 时才显示“任务已完成”。
- 失败与取消分别显示“任务执行失败”和“任务已停止”，与底部实时推理状态不会同时出现。
- 历史记录中旧版“本阶段已完成：检测到模型……”会在展示时转换为“执行恢复”，SQLite 原始审计记录保持不变。

## 验证范围

- 首次为空、第二次成功。
- 连续空回复与仅 reasoning 回复。
- 含历史空 assistant 的旧会话直接重试。
- 非流式恢复。
- API 空成功拒绝与缺失 token 补发。
- Web2 零输出报错、重试和持久化消息恢复。
- Harness 未受信时的连续计划回复阻断、流式文本不泄漏、真实 `file_write` 成功、no-op 写入失败、内部状态工具排除。
- 动作纠正轮返回空内容后，仍能继续强制写入并完成真实文件变更。
- Web2 连续恢复轮次聚合、终态文案和运行中单一过程标题。

## 当前限制

历史纠正采用读取时投影，不改写既有 SQLite 原始记录，以保留审计原貌。只有同时满足“完成状态、默认空摘要、无 response step”的记录才会被识别，避免误判旧版正常运行。

当前 Windows 环境中的 `bash_run` 子进程对 PowerShell 与常见 Unix 命令的兼容仍不稳定；本次真实 Run 中两次 shell 检查失败后，Agent 已改用 `file_read` 完成回读。该问题不影响动作门禁和文件产物，但应作为独立的 shell 运行时问题处理。
