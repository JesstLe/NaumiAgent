# Web2 空回复恢复

## 问题

模型可能结束调用但既不返回正文，也不返回工具调用。旧实现会保存空的 assistant 消息，并把运行标记为 `completed`。Web2 会过滤空消息，最终只剩“已完成”的执行状态，看不到答复。

## 实现

- ReAct 流式与非流式路径都把非空用户可见正文作为成功条件。
- 会话加载与每次模型调用前都会清除旧版遗留的空 assistant 消息；带 `tool_calls` 的合法空正文 assistant 会保留，并继续补齐工具结果。
- 第一次空回复会自动重试一次，并发布公开的恢复阶段摘要。
- 第二次仍为空时，不保存空 assistant 消息；运行写入失败的 response step，并返回中文错误。
- SSE API 校验成功终态必须有正文；若引擎已有正文但遗漏 token 事件，API 会补发正文。
- Web2 在零 token 终态后重新读取持久化消息；仍没有新答复时展示可重试错误。
- 已保存为 `completed`、没有 response step 且回执为默认空摘要的历史运行，在 API 展示层按失败记录呈现。

## 验证范围

- 首次为空、第二次成功。
- 连续空回复与仅 reasoning 回复。
- 含历史空 assistant 的旧会话直接重试。
- 非流式恢复。
- API 空成功拒绝与缺失 token 补发。
- Web2 零输出报错、重试和持久化消息恢复。

## 当前限制

历史纠正采用读取时投影，不改写既有 SQLite 原始记录，以保留审计原貌。只有同时满足“完成状态、默认空摘要、无 response step”的记录才会被识别，避免误判旧版正常运行。
