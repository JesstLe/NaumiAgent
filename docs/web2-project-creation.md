# Web2 项目、工作目录与会话绑定

## 实现范围

- “项目”标题右侧的加号打开“创建项目”弹窗，不再与“新建侧边聊天”混用。
- 第一步选择项目类型；本地项目可用，远程项目在尚未接入远程主机协议时明确禁用。
- 第二步填写项目名称并通过桌面端原生 Windows 文件夹选择器选择源文件夹。选择后自动使用文件夹名称填充项目名，仍可手动修改。
- 创建项目会用所选目录启动新的 NaumiAgent daemon，轮询确认新服务返回的 `workspace_root` 与所选目录一致，然后切换 API 地址并刷新界面。
- 项目名称、路径、类型、创建时间和最近打开时间通过 shared 项目注册表保存。侧边栏显示已登记项目；点击其他本地项目会执行同一套 daemon 切换流程。
- 会话创建时立即由后端绑定当前 `workspace_root` 和 Git 分支。文件读写、终端、来源文件、Diff 和 Agent 工具继续使用该 daemon 的真实工作目录。
- 打开其他项目的历史会话时，前端先切换 daemon 并确认返回的 `workspace_root`，再恢复目标会话。不会把 A 项目的会话放到 B 项目目录执行。
- 侧边栏按每个会话持久化的 `workspace_root` 分组，同时展示多个项目的历史会话；旧版未绑定的空会话只归入当前项目。

## 共用底层

- 项目注册表位于 `frontend/shared/src/projects/workspaceProjects.ts`，不依赖 Web2 组件，Web 与桌面壳可复用。
- 文件夹选择、daemon 配置和启动继续通过 `PlatformAdapter`，没有在 Web2 中复制 Tauri 调用。
- 浏览器无法得到可用于启动本地 daemon 的绝对文件系统路径，因此弹窗会说明需使用桌面版，不提供伪造的浏览器目录选择。
- `SessionStore`、`SessionPort` 与 `AgentEngine` 共同执行会话目录绑定；即使其他客户端绕过 Web2，Engine 也拒绝在错误工作区加载已绑定会话。

## Codex / Claude 对齐原则

- 项目代表一个明确的本地根目录，不是仅用于展示的标签。
- 新对话属于当前项目；进入其他项目或它的历史会话时，先切换运行环境。
- 会话的工作目录一经产生历史记录就不能被另一个项目静默覆盖。
- Windows 文件夹选择器允许选择已有目录，也允许在选择器内新建文件夹。
- 项目名称可自定义，真实路径始终保留并用于执行和审计。

## 当前边界

- 一个桌面窗口一次连接一个工作区；切换项目会停止当前受管 daemon 并启动目标项目 daemon。
- 远程项目需要远程主机发现、认证、目录浏览和进程生命周期协议。当前仓库尚无该协议，所以只展示禁用入口。
