# UI-15.5a New UI 触摸板滚动意图控制器

## 1. 交付结论

本切片把 New UI 原先“每 32ms 接受一个同方向事件，其余直接丢弃”的节流器，替换为有界滚动意图
控制器。目标是让慢滑仍能逐行定位、快速滑动按稳定节拍推进，并避免手指停止后继续跳过多行。

它只改变普通对话 Timeline 的终端滚轮/应用光标输入，不改变 PageUp/PageDown、Home/End、输入历史、
专页内部导航或后端协议。

## 2. 状态机

`createTrackpadScrollController()` 维护四项进程内瞬时状态：

- 最近一次实际输出的方向；
- 最近一次实际输出时间；
- 最近一次合法输入时间；
- 最多一个待输出方向；
- 最多一个 48ms 定时器。

行为规则：

1. 首个合法方向立即输出一行，不引入首触延迟；
2. 同方向高频 burst 在 48ms 窗口内合并为最多一个待输出行；
3. 定时器到期时，只有最近 24ms 仍收到同方向输入才输出这一行；短手势停止后直接丢弃待输出行；
4. 方向反转立即取消旧方向待输出行，并立刻输出新方向；
5. 时钟回退、非有限时间和未知方向失败关闭；
6. UI shutdown 时取消待输出定时器，退出后不再修改 Timeline。

因此事件生产速度不能直接扩大滚动距离。持续滑动时上限约为每秒 20.8 行；短手势不会在手指停止后
补出第二行，单次轻滑仍是精确一行。

## 3. Timeline 与持久化

实际步进继续调用共享 `scrollTimeline()`：

- 向上离开尾部时进入 detached 状态；
- 向下回到 offset 0 时恢复 follow-tail 并清空 unread 计数；
- 新输出不会强行把 detached 用户拉回尾部。

滚动状态改用已有 100ms debounce 保存，不再为每个被接受的滚动事件同步写 UI snapshot。绘制仍进入
既有 redraw scheduler，不绕开帧调度。

## 4. 验收证据

定向 Node 测试覆盖：

- 首步立即输出，持续 burst 以 48ms 节拍产生下一行；
- 短手势中的 1,000 次瞬时事件也不会在停止后补出第二行或积累长惯性队列；
- 方向反转取消旧方向动量并立即响应；
- dispose 清理定时器，异常方向和异常时间不产生步进；
- 原有 follow-tail、unread 去重与回到尾部语义保持不变；
- `index.js` 与 `scroll-input.js` 通过语法检查。

## 5. 自我审视与边界

- 大多数终端只把触摸板滚动暴露为离散方向序列，当前输入合同没有像素或小数 delta，因此本切片不能
  伪造真正的亚行滚动；它提供的是逐行、匀速、有界合并。
- Textual TUI 走其自身 mouse/scroll 事件系统，没有共享 Node 控制器；UI-15.5b 已通过应用级
  sensitivity 补齐离散滚轮逐行定位，但两端都没有伪造 fractional delta。
- Windows Terminal、iTerm2、Terminal.app 和 Linux 主流终端的真实设备录制尚未进入 UI-17.4 发布矩阵。
- 若后续终端 capability 能提供 wheel delta，应新增归一化合同和设备矩阵，而不是扩大当前待输出队列。
