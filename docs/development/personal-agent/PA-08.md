## 3. 不可变版本与真实内容

- `artifact_id=art_<32hex>` 代表逻辑资料，整数版本代表一次不可变内容及来源快照。
- CAS 修订使用 `expected_version`。并发修订只有一个成功，旧聊天和旧引用继续指向原版本。
- 相同内容可以具有新的逻辑版本；blob 可按 SHA 去重，不吞掉修订身份。
- 请求编号绑定确切操作、正文摘要、版本与授权参数。同 request ID 改内容发生冲突，
  网络结果不明时保留原请求，不换编号来掩盖未知状态。
- 实际字节、大小、MIME、完整 SHA 与版本证据一起保存。每次读取校验实际 blob，
  不是只检查路径存在或元数据声称已生成。
- blob 先原子落盘、元数据事务未完成时，原请求可复用确切 blob；不会把未提交记录伪装成新版本。
- SQLite 版本行具有不可变触发器、摘要与版本头锚点；缺失或篡改返回明确存储错误，不返回空目录掩盖故障。
- 公共文件验证上限 20 MB。严格 JSON 拒绝重复 key、NaN/Infinity、深度/数量超限和无效编码。
  图像用实际解码校验，SVG 禁外部资源与脚本。
- PDF 使用 `pypdf` 的 strict 结构解析及有界页面树；拒绝加密、无页、超过 1000 页、
  页数不符、目录损坏和循环引用。不主动展开全部内容流，不将结构检查称为语义提取或渲染。
- 私有 blob 位于独立 broker 存储，不返回其宿主路径。仅随机目录名不是隔离证明，进程边界另见第 5 节。

## 4. 精确分享、团队快照与撤销传播

引用绑定以下五项：

```json
{
  "artifact_id": "art_...",
  "version": 1,
  "sha256": "<full-content-sha256>",
  "grant_id": "asg_...",
  "grant_revision": 1
}
```

- 只有自有资料使用空 grant/revision 0；接收者不能把 grant 置零冒充 owner。
- 分享只覆盖指定版本，不自动授予将来版本。只获 v1 的 Agent 看不到未分享 v2 的标题或内容。
- 原分享 request 重放返回原 grant 的当前状态，已撤销的 grant 不被复活；重新分享产生新的明确授权。
- 团队分享冻结团队 ID、版本、所有祖先关系和实际去重叶子成员。后加入成员没有旧授权；
  真实团队关系、启用状态或版本变化会要求重新确认，不悄悄刷新旧快照。
- `get_grant()` 用于核原 ref 指定的 grant；`access_grants()` 收集实际内容及来源依赖的授权。
  即使同一 Agent 另有个人 grant，原 Session 的失效团队 grant 也不能被默认读取路径替换。
- 衍生内容内部保存原读取者与原 grant 依赖；修订不能删掉旧来源来洗掉撤销。
  分享衍生内容时，接收 Agent 及团队每位冻结成员还必须能读全部上游版本。
- Session refs 幂等 union、不可清空。模型不能通过下一次调用传空 source_refs，
  让已读私有内容变为无来源的自由输出。
- 资料接纳、来源组装、每次模型和工具执行边界、结果发布前都保留重新核验入口。
  撤销后停止后续访问；已经合法读取或下载的历史字节不能被声称已远程收回。
- 主 Agent 含私有 refs 的会话不执行 global memory 自动提取，避免通过自动记忆扩大资料范围。
  这不是 PA-02 的完整个人记忆实现。

## 5. 私有文件与实际执行隔离

私有资料环境中的 `bash_run/code_execute` 接入真实 Docker executor：

- 仅接受本机 Unix socket 或 Windows Docker named pipe；拒绝远程 daemon/context 后再传宿主路径。
- 使用已有明确镜像并解析确切 image ID；不隐式 pull，不因镜像/daemon 失败静默切回本机执行。
- network none、UID 65534、只读 rootfs、capabilities 全降、no-new-privileges，
  CPU/内存/PID/超时均有限额；不传模型凭据、宿主 home、Docker socket或任意父环境。
- 私有计算读取有界公共工作区快照及本次确切输入；`/workspace` 与 `/inputs` 只读，
  不把原工作区作为可写宿主挂载。公开快照排除运行数据、`.git`、依赖和缓存等保护目录。
- 只有独立 `/outputs` 的真实普通文件交给 broker；校验 links、大小、数量、读取期间变更，
  再以实际 source refs 发布为产物，不向共享工作区偷偷导出私有结果。
- 本机 file/read/glob/grep/import/output_publish 等入口使用私有路径及 alias guard。
  Windows reparse/junction、硬链接、越界或受保护路径不能靠换拼写绕过。
- 取消或超时只清理由随机 run label 与实际 container ID 同时核验的容器；
  二次查询确认已移除。清理运输不确定保留 `cleanup_unknown`，不改成成功。
- 当前这是有界隔离计算环境，不是完整依赖构建环境或 PA-11 的全电脑控制。

**未接入的浏览器路径：** 当前 `browser_*` 尚未进入私有资料的隔离浏览器执行环境，
因而停止该路径，而不是让宿主 CDP 接触本机管理 API、凭据或其他 Agent 的资料。
这属于明确未完成的 PA-11 能力，未从原 24 项要求中删除。

### 读取不切换执行身份

- 所有 Workbench GET、事件 WS 使用持久会话及显式 session_id 的 service，保留工作区校验，不调用 Engine.load_session、不恢复归档状态、不推进授权代次。
- Task 摘要使用 task_store.scoped(session_id)，不借用当前 Agent 的 active scope。
- 需要切换 Engine 的 Workbench 写操作由同一 engine_lock 覆盖完整业务动作；事件 socket 不持有终身锁。
- 审批答复属于显式例外：只对目标 session 的 approval 写入，不切换 Engine、不等待正在执行的长锁，避免执行等审批、审批等执行的死锁。
- Engine.run/run_streaming 使用内存中的活跃执行 lease，不另造 Run 状态机；活跃期间连同 ID 重载也被拒绝，空闲时仍可正常切换。
- 模型、工具、消息追加和最终保存重核 session/actor/version；隔离计算在开始时冻结 session_id/run_id，返回真实 Library URL，不事后从另一会话推断“最新 Run”。
