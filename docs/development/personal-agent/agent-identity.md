# Agent 身份与分工

日期：2026-11-05

## 用户决定

持久对象统一称为 **Agent**，不以“xx 员”或“专员”定义产品类型。
初始只有主 Agent；主 Agent 仅按用户明确要求创建其他 Agent 或团队。
研究、运营、内容、投资、工作和生活是可调整的任务方向，不是预置职业。
用户决定名称；名称与职责分开保存。调整分工不改变 Agent ID、不重建会话、不覆盖历史，
也不自动为已有名称追加后缀。用户主动指定的职业式名称仍原样保留。

## 本次实现

- 已有浅色界面、CLI/TUI 与主 Agent 规则已经使用 Agent，保持现有交互，不增加解释性 UI 文案。
- Tool 与 HTTP/OpenAPI 的 `kind` 补齐兼容语义，名称字段说明用户名称与职责分离。
- 工具发现使用 independent agent；主 Agent 提示中的目录身份不再称为职业角色。
- 产品入口、24 项能力的当前标题、需求与验收统一为 Agent；新增机器可读的身份约定。
- PA-00/PA-06 的现行合同使用 Agent；历史验收输入、对象名称、ID、视频观察、状态与结果保留。

`kind=specialist` 是现有非团队持久 Agent 的兼容协议值，不表示固定职业；`team` 表示团队。
本次不修改枚举、数据库 CHECK、Session 绑定、授权范围、请求幂等或历史记录，也不执行数据迁移。
