完整专员双向消息、团队会话执行与产物版本交接仍待后续切片。全产品目标保持 24 项，不缩减。

## 本切片的真实行为

- 初始只存在主助理；本模块不创建任何常驻角色。每个步骤必须引用用户已创建的专员 ID 与配置版本。
- 主助理可以通过 `personal_agents(operation=collaborate)` 派发真实任务；Web 与 CLI/TUI 使用相同 service。
- 1–12 步 DAG、串行接力、并行分支与汇总依赖；失败、取消、超时和 UNKNOWN 不解锁下游。
- 每步独立 `Session`、`AgentEngine`、`ChatRun` 和 `AgentJob`，不切换主助理当前会话、不覆盖专员日常聊天。
- 交接仅包含用户填写的显式 context 与前置步骤的确切结果，绑定 `agent_id/version`、Job ID 和 `result_sha256`。
- 私有聊天、主会话其他内容、其他专员资料、全局记忆均不自动复制。
- 执行记录保持只读；Web 输入、编辑、重试、上传与记录修改入口均锁定，可打开专员的日常对话继续交流。
- 名称显示使用对应历史版本，不用新版名称伪装旧职责版本。
- 明确点名已有专员的请求由主助理直接处理，不被规划器替换成临时角色。
- 工具与模型执行前重查专员状态、职责版本与租约；权限确认返回后再次检查。配置撤销不会因 bypass 绕过。
- 用户改变权限策略后旧请求停止；恢复仍使用原请求身份，不改成新请求重复派发。
- 使用已有权限确认 Broker，以真实子会话/call_id 匹配；协作页面显示待确认操作与参数，只提供本次允许/拒绝。
- 专员可以调用真正的 `request_user_input`；选择或自定义回答绑定协作、步骤和问题 ID。
  回答持久化并去重；过期、已取消和已结束的问题不继续接收决定，助手不代用户选择。
- 服务在线时独立于页面执行，关闭页面不取消任务；重开读取真实状态与产物回应。

## 权威边界与恢复设计

### 协作日志不是第二个执行状态机

`personal/collaboration_store.py` 保存不可变计划、执行身份、取消意图和顺序事件。
其 schema 没有 Job `state/status/result/response` 字段。

`daemons/agent_jobs.py` 仍是唯一执行状态权威，负责加密任务/结果、原子入场、容量、租约、epoch fencing、终态及回执。
`runs/` 仍负责用户能打开的运行记录和工具证据。UI 状态从这些权威记录投影，不由模型文字或进程内 message bus 推断。

每份请求先写 `dispatch_prepared`，再调用 `AgentJobStore.admit_for_capacity`。
准备记录包含不可变 worker request；其 Job ID 通过既有请求摘要规则计算。
入场和 journal 回执之间退出时，下一次恢复识别同一 Job，不因上下文或策略变化另建执行。
专员执行使用独立的 AgentJob 数据库命名空间，避免临时 AgentWorker supervisor 领取错误执行协议的 Job；
复用的仍是原 AgentJobStore，不新增执行生命周期实现。

并行数和持久等待容量继承 `safety.max_parallel_agents / max_queued_agents`。
协作计划按创建顺序进入调度；等待队列已满时保留准备计划，不超额入场。
`max_queued_agents=0` 仍可在容量释放后继续，不丢任务或形成死锁。

### 重启、取消与不明结果

- 未入场计划可从原身份继续；已完成 Job 不重跑。
- 仅过期且尚未运行的 claim 可以再次取得。
- 已运行且租约过期、没有可信终态回执的 Job 收口为 UNKNOWN，阻断依赖，不自动重试外部动作。
- `cancel_requested` 仅表示用户要求停止，不提前冒充已停止；活跃 owner 结束执行后提交真实终态。
- 取消调用是幂等的，避免重复 `Task.cancel()` 打断终态回执的写入。
- AgentJob 终态已存在而 journal result 尚未写入时，根据原回执恢复 journal。
- 回滚只恢复源码副本，不删除任何用户资料库，也不承诺撤销已经产生的外部效果。

### 独立 Engine 的隔离

child 使用独立的 SessionStore、router、工具执行器与资源；只有 Session/ChatRun 的数据库位置相同。
浏览器、worker、授权、目标、后台任务、调度、harness 与 evolution 资源位于每步独立目录。
child 不启动长期服务；构造/关闭不会接管父 Engine 的 analysis router、subagent manager 或 pursuit 全局依赖。
worker 使用新的 Context，避免继承父 Run 的临时授权上下文。

## 使用入口

### Web

“我的助理” → “协作” → 选择已有专员 → 填写每步任务 → 依次接力或并行执行 → 共享上下文 → 开始协作。
列表可重开原任务，查看各步结果、职责版本、交接日志、工具事件、问题与确认；停止操作有明确确认。
布局为浅色，已检查 1440 / 768 / 390 宽度；结果复用现有 Markdown 渲染器，
正确显示标题、加粗、列表和表格，阻止原始 HTML 与脚本链接。

### Tool

```json
{
  "operation": "collaborate",
  "request_id": "budget-review-v1",
  "title": "预算复核",
  "context": "只读取用户指定的 budget.csv，金额单位为元。",
  "steps": [
    {"id": "calculate", "agent_id": "pa_<真实ID>", "agent_version": 1,
     "task": "读取指定文件，核算剩余预算。", "depends_on": []},
    {"id": "verify", "agent_id": "pa_<另一真实ID>", "agent_version": 1,
     "task": "独立读取原文件并复核前置结论。", "depends_on": ["calculate"]}
  ]
}
```

Tool 默认使用当前真实源会话，不接受冒用其他源会话。
常驻专员不因本模块自动获得目录管理或跨角色委派权限。

### CLI / TUI

```text
/assistants collaborate-json '<完整JSON对象>'
/assistants collaborations
/assistants collaboration <协作ID>
/assistants cancel-collaboration <协作ID>
/assistants reply-json <协作ID> <问题ID> '{"kind":"option","value":"选项值"}'
```

命令通过同一个 `personal_agents` Tool 执行，保留已有工具权限链。
协作受理不等于完成；查询原 ID 后才能报告真实结果。

### API

均继承现有 API 身份验证：

- `POST /personal/collaborations`
- `GET /personal/collaborations?source_session_id=...`
- `GET /personal/collaborations/{id}`
- `POST /personal/collaborations/{id}/cancel`
- `POST /personal/collaborations/{id}/questions/{request_id}/reply`
- 子执行授权复用 `POST /sessions/{session_id}/permissions/{call_id}/resolve`

参数为严格 schema；来源会话校验工作区/归属；错误有中文文案，版本与幂等冲突返回 409。
