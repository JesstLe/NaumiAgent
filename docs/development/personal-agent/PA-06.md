## 本切片的真实行为

- 初始只存在主 Agent；本模块不创建任何常驻角色。每个步骤必须引用用户已创建的Agent ID 与配置版本。
- 主 Agent可以通过 `personal_agents(operation=collaborate)` 派发真实任务；Web 与 CLI/TUI 使用相同 service。
- 1–12 步 DAG、串行接力、并行分支与汇总依赖；失败、取消、超时和 UNKNOWN 不解锁下游。
- 每个 DAG 步骤独立 `Session`、`AgentEngine`、`ChatRun` 和 `AgentJob`，不切换主 Agent当前会话、不覆盖Agent日常聊天。
  步骤内同步互询有独立接收方 Session/Engine/Run，但不另建 AgentJob，执行权威继续来自根步骤 Job。
- 交接仅包含用户填写的显式 context 与前置步骤的确切结果，绑定 `agent_id/version`、Job ID 和 `result_sha256`。
- 私有聊天、主会话其他内容、其他Agent资料、全局记忆均不自动复制。
- 执行记录保持只读；Web 输入、编辑、重试、上传与记录修改入口均锁定，可打开Agent的日常对话继续交流。
- 名称显示使用对应历史版本，不用新版名称伪装旧职责版本。
- 明确点名已有Agent的请求由主 Agent直接处理，不被规划器替换成临时角色。
- 工具与模型执行前重查Agent状态、职责版本与租约；权限确认返回后再次检查。配置撤销不会因 bypass 绕过。
- 用户改变权限策略后旧请求停止；恢复仍使用原请求身份，不改成新请求重复派发。
- 使用已有权限确认 Broker，以真实子会话/call_id 匹配；协作页面显示待确认操作与参数，只提供本次允许/拒绝。
- Agent可以调用真正的 `request_user_input`；选择或自定义回答绑定协作、步骤和问题 ID。
  回答持久化并去重；过期、已取消和已结束的问题不继续接收决定，助手不代用户选择。
- 服务在线时独立于页面执行，关闭页面不取消任务；重开读取真实状态与产物回应。

## 权威边界与恢复设计

### 协作日志不是第二个执行状态机

`personal/collaboration_store.py` 保存不可变计划、执行身份、取消意图和顺序事件。
其 schema 没有 Job `state/status/result/response` 字段。

`daemons/agent_jobs.py` 仍是唯一执行状态权威，负责加密任务/结果、原子入场、容量、租约、epoch fencing、终态及回执。
`runs/` 仍负责用户能打开的运行记录和工具证据。UI 状态从这些权威记录投影，不由模型文字或进程内 message bus 推断。

每份请求先写 `dispatch_prepared`，再调用 `AgentJobStore.admit_for_capacity`。
准备记录包含不可变 worker request；其 Job ID 通过既有请求摘要规则计算。
入场和 journal 回执之间退出时，下一次恢复识别同一 Job，不因上下文或策略变化另建执行。
Agent执行使用独立的 AgentJob 数据库命名空间，避免临时 AgentWorker supervisor 领取错误执行协议的 Job；
复用的仍是原 AgentJobStore，不新增执行生命周期实现。

并行数和持久等待容量继承 `safety.max_parallel_agents / max_queued_agents`。
协作计划按创建顺序进入调度；等待队列已满时保留准备计划，不超额入场。
`max_queued_agents=0` 仍可在容量释放后继续，不丢任务或形成死锁。

### 重启、取消与不明结果

- 未入场计划可从原身份继续；已完成 Job 不重跑。
- 仅过期且尚未运行的 claim 可以再次取得。
- 已运行且租约过期、没有可信终态回执的 Job 收口为 UNKNOWN，阻断依赖，不自动重试外部动作。
- `cancel_requested` 仅表示用户要求停止，不提前冒充已停止；活跃 owner 结束执行后提交真实终态。
- 取消调用是幂等的，避免重复 `Task.cancel()` 打断终态回执的写入。
- AgentJob 终态已存在而 journal result 尚未写入时，根据原回执恢复 journal。
- 回滚只恢复源码副本，不删除任何用户资料库，也不承诺撤销已经产生的外部效果。

### 独立 Engine 的隔离

child 使用独立的 SessionStore、router、工具执行器与资源；只有 Session/ChatRun 的数据库位置相同。
浏览器、worker、授权、目标、后台任务、调度、harness 与 evolution 资源位于每步独立目录。
child 不启动长期服务；构造/关闭不会接管父 Engine 的 analysis router、subagent manager 或 pursuit 全局依赖。
worker 使用新的 Context，避免继承父 Run 的临时授权上下文。

Windows 资源路径使用稳定短摘要命名：根目录为
`personal-executions/<根JobID的SHA256前32位>/`；接收方位于其下的
`p/<消息ID去除pm_前缀>/`。各资源字段再使用字段名 SHA256 的前 12 位作为独立命名空间，
避免长 Job ID、长字段名与嵌套 peer 目录叠加；完整不可变身份仍保存在 Job/消息记录中，不靠文件名替代身份验证。

## Agent双向消息合同

### 显式范围与真实接收方执行

- 本模块不创建预设角色。发送与接收双方均引用用户已创建的Agent及确切职责版本。
- 普通协作默认没有互询范围；`peer_agents` 显式绑定每位可询问Agent的 ID、版本和工具。
  手动消息中用户明确选择的接收方构成本次收件范围，不自动开放目录中的其他角色。
- 发送方必须已配置 `personal_message`。接收方实际工具是档案工具与本次 grant 的交集，
  模型 schema 和真正的工具执行入口同时限制；bypass 不绕过Agent身份或工具范围。
- grant 省略 `tool_names` 时，只选择真实 registry 标记为 `read_only` 的工具，
  加上档案中已配置的 `personal_message`。没有工具元数据不默认授权；写入与 shell 必须逐项明确选择。
- 请求仅传显式 `content/context`，不复制日常私有聊天、主 Agent历史或其他Agent记忆。
  对端使用新 Session、独立 Engine 和真实 ChatRun；不是在发送方聊天里伪装多个发言角色。
- 活跃同步调用链共用根 AgentJob 的 owner/epoch/lease、容量名额和预算 tracker；
  **inline 接收方没有独立 AgentJob**。父Agent等待对端期间不继续模型执行，
  避免 `max_parallel_agents=1` 时因父任务占满容量、接收任务排队而死锁，也不临时增加容量上限。
- 同一 actor 的多个请求串行处理；嵌套接收方使用新的 actor context。
  不同新问题可以再次询问同一Agent，但拒绝重复祖先问题；深度最多 8，每根步骤最多 32 条消息。
- 根租约、活跃叶子会话、取消、有效期、双方版本和暂停状态在执行边界重查。
  根 Job 用共享 tracker 汇总所有真实消耗，各 Run 只记录自己的直接调用用量，避免重复计费。

### 持久 outbox、回执与恢复

`personal/message_store.py` 保存稳定 `pm_...` 身份、不可变请求、双方版本、根步骤/Job、
源 Run、接收方 Session/Run，以及发送、接收、结果和确认回执；不新增另一套 Job 生命周期。

- 相同请求身份与载荷复用原消息；同一身份改变正文、共享资料、版本或工具范围产生冲突。
- 首次派送使用原子 claim，只有一个赢家；已开始的派送不重新领取，不因重启另建接收方 Run。
- 手动发送先形成持久根协作与待发消息；worker 通过真实 `personal_message` Tool 调用派送，
  并记录发送方 Run，不要求发送方 LLM 假装发送。接收方仍由真实模型执行。
- 未开始的手动 outbox 通过原根协作 admission/恢复继续，沿用原请求和授权快照；
  根执行已结束或角色已停用/改版的未派送消息投影为停止/受阻，不永远显示等待。
- 派送已开始却没有可信终态、原 owner/epoch 失效或 lease 过期时保留 UNKNOWN，
  可打开原 Run 核查，不自动重跑。根 Job UNKNOWN 与消息是否已有确切结果是两个独立事实。
- 完整回答（上限 2 MiB）、正文 SHA256、结果绑定摘要、实际用量与 Run receipt 持久保存。
  重复读取/发送返回原回答，不以 Run 摘要替代原正文；Tool 长回答支持分页，API 与界面可读取完整正文。
- 回执链保存持久头摘要和计数锚点；尾部删除也会被校验发现。
  内部 `dispatch_token` 与 owner 资料不暴露给 Tool/API/UI。
- ACK 必须提供原回答的 `expected_response_sha256`。`acknowledged_by` 保留首次确认来源，
  用户点击“确认收到”不冒充发送Agent已经读取回答；打开界面本身也不产生已读回执。

### 执行历史与交互归属

`Session.personal_execution_id` 是不可变执行 marker，和Agent归属一起写入实际会话库。
旧快照保存、并发保存、复制和归档/恢复均保留该 marker；旧执行会话迁移只更新 marker，
不重写消息。消息/协作索引丢失时，执行记录仍保持只读，不降级成主 Agent或可写的日常Agent会话。

对端权限确认与问题复用原 Broker，绑定根步骤、`peer_message_id`、真实接收方 session/call identity，
显示实际执行Agent。过期或已结束的接收分支不再接收回答，主 Agent或其他会话身份不能代替对端授权。

## 使用入口

### Web

“我的 Agent” → “协作” → 选择已有Agent → 填写每步任务 → 依次接力或并行执行 → 共享上下文 → 开始协作。
列表可重开原任务，查看各步结果、职责版本、交接日志、工具事件、问题与确认；停止操作有明确确认。
布局为浅色，已检查 1440 / 768 / 390 宽度；结果复用现有 Markdown 渲染器，
正确显示标题、加粗、列表和表格，阻止原始 HTML 与脚本链接。

协作表单可以选择显式互询范围与工具；“发送消息”选择真实发送/接收Agent、正文与共享资料。
双方对话按需加载完整回答、展示双方版本与原回执，并链接实际执行会话。
响应不确定时固定首次完整 payload、来源和 request_id，原样重试，不自动换 ID 或放宽旧授权。
协作和消息表单分别保存草稿。用户确认和Agent确认分开展示，旧轮询快照不覆盖已核实的确认事实。
本轮这些界面已完成组件与 fixture 视觉验证；真实后端浏览器闭环待本轮集成补充。

### Tool

```json
{
  "operation": "collaborate",
  "request_id": "budget-review-v1",
  "title": "预算复核",
  "context": "只读取用户指定的 budget.csv，金额单位为元。",
  "steps": [
    {"id": "calculate", "agent_id": "pa_<真实ID>", "agent_version": 1,
     "task": "读取指定文件，核算剩余预算。", "depends_on": []},
    {"id": "verify", "agent_id": "pa_<另一真实ID>", "agent_version": 1,
     "task": "独立读取原文件并复核前置结论。", "depends_on": ["calculate"]}
  ]
}
```

Tool 默认使用当前真实源会话，不接受冒用其他源会话。
常驻Agent不因本模块自动获得目录管理或跨角色委派权限。

`personal_agents` 的 `message_send` 发起手动消息；`messages/message` 查询双方记录，
`message_ack` 记录用户确认。`collaborate` 可附 `peer_agents`。
执行中的Agent通过专用 `personal_message` 工具的 `peers/send/get/inbox/ack` 操作互询；
发送者、源会话、根 Job/epoch 与调用链由绑定 context 决定，不接受模型参数伪造。

### CLI / TUI

```text
/assistants collaborate-json '<完整JSON对象>'
/assistants collaborations
/assistants collaboration <协作ID>
/assistants cancel-collaboration <协作ID>
/assistants reply-json <协作ID> <问题ID> '{"kind":"option","value":"选项值"}'
/assistants message-json '<完整JSON对象>'
/assistants messages <协作ID>
/assistants message <消息ID>
/assistants message-ack <消息ID> <回答SHA256>
```

命令通过同一个 `personal_agents` Tool 执行，保留已有工具权限链。
协作受理不等于完成；查询原 ID 后才能报告真实结果。

`message-json` 使用 `sender_agent_id/sender_agent_version`、
`recipient_agent_id/recipient_agent_version` 和 `content`；可附 `context`、稳定 `request_id`、
`peer_agents` 及原始来源会话。手动发送返回根协作，不立即冒充对端已经收到或执行完毕。
`message` 显示完整多行正文与回答摘要，不静默截为列表摘要。

### API

均继承现有 API 身份验证：

- `POST /personal/collaborations`
- `GET /personal/collaborations?source_session_id=...`
- `GET /personal/collaborations/{id}`
- `POST /personal/collaborations/{id}/cancel`
- `POST /personal/collaborations/{id}/questions/{request_id}/reply`
- `POST /personal/messages`：创建手动消息根协作，返回协作记录
- `GET /personal/collaborations/{id}/messages`：消息摘要列表

参数为严格 schema；来源会话校验工作区/归属；错误有中文文案，版本与幂等冲突返回 409。
