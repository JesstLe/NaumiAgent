## 原范围与本轮顺序

1. 周期委托：自然语言/结构化规则、once/cron、IANA 时区、交易日日历、开关、真实执行与送达。
2. 每日安排、跨工作区事项汇总、截止时间跟进和有原事件来源的下一步建议。
3. 通知合并、勿扰、持久收件与人工已读分离。
4. 跨修订/重启的总执行次数、估算费用上限及真实完成率、纠正、重复、误提醒、交付耗时。

初始只有主 Agent；周期只绑定用户已经创建的 Agent，不创建或重命名持久身份。

## 周期与一次执行分离

`Routine → 不可变 nominal occurrence → 既有 once PersonalItem → AgentJob / Run / Library / inbox`。
PA-01 的 ItemStore 保持 schema v1、旧定义和 hash；不把 cron 塞进旧 once 字段，不产生第二套执行器。
周期父规则有独立 owner-bound journal、修订、请求回执、游标、预留及租约。每个发生以原定 UTC
时刻和 series epoch 定位，不用实际恢复时刻或标题产生执行身份。改标题/模板不重置累计预算。

日历与 cursor/occurrence/额度在短事务中提交；向 Item 的桥接使用稳定原 request_id。响应未知时
查原回执，不创建新 Item、Job 或 Run。并发、崩溃及暂停期间的旧发生须保留可解释的机械决定。

## 日历合同

旧 Scheduler reminder 的主机时区、DOM/DOW AND 与离线合并语义不变。新规则为显式版本化的
crontab OR、IANA 时区、gap skip、fold first/second/both；实际 TZif SHA 冻结，时区数据变化需重核。
交易日使用 `exchange-calendars` 的真实 session snapshot，保存包版本、范围和内容 SHA，不把
周一至周五当交易日。XSHG 当前包仅覆盖至 2026；未知覆盖明确停止，不猜测下一年。
规则型交易日历是锁定版本的投影，不宣称实时确认临时停市。

misfire 明确为 skip/latest/catch_up；每轮有界，合并记录精确覆盖数量和范围。overlap 为
queue/skip/allow，串行 UNKNOWN 不自动解锁。暂停停止后续受理；已运行与取消使用原 Job 的真实语义。

## 次数、费用与来源边界

在桥接 Item 前持久预留启动名额与有限单次费用；重复发生不重复扣额度。执行、预留、已知费用与
未知占用分开显示；缺用量不补零、不释放未知费用、不重放旧 Run 来补证据。每次模型 transport
也要在已核验单价和有限 output 上界下预留，覆盖重试与压缩调用。这里约束本地估算消耗，
不把 `RunUsage.billing_authority=False` 的数据称为 provider 最终账单硬上限。

新周期子 Item 引用 `authority_version=3` 的真实私有资料，绑定原 routine/occurrence。新执行边界
核验原规则、发生及预留；旧 ArtifactStore 对未知来源版本拒绝，避免源码回退后绕过周期控制继续付费。
旧普通资料与 PA-03 的 v2 来源保持兼容。历史报告读取与新执行授权分开，不因暂停隐藏已交付报告。

## 共享入口与界面

独立 `personal_routines` Tool、`/routines` CLI/TUI、强认证 REST 与浅色周期工作区共享同一 service。
保存/启用前展示实际近期触发、时区、Agent、次数及估算额度。提议、已创建、启用、触发、执行、
送达分别从原事实显示，不制造统一“成功”布尔值。未知请求仅持久 opaque IDs，不缓存正文或材料。
