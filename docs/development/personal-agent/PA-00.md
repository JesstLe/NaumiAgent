## 已实现

- 初始只有主 Agent，Agent目录为空；不预置运营、投资、研究等角色。
- 用户通过对话、Web 或 `/assistants` 要求创建时，生成真实持久身份与职责版本。
- owner-local SQLite catalog：档案、历史、状态、请求幂等、团队成员和会话归属。
- 稳定 request_id 与内容绑定，版本 CAS 防止重复建人和并发覆盖。
- 每个Agent在每个工作区/session DB 下拥有独立 Session，重启后保持。
- Session 的 `personal_agent_id` 一旦绑定，不被 stale save 清空或替换；
  catalog 缺失或映射不一致时停止执行，不降级为主 Agent。
- 每轮校验职责、模型层级、工具范围与版本；确认等待、模型重试后再次校验。
- 原引擎、执行器、权限、预算和 ChatRun 继续负责执行，不创建竞争的执行系统。
- 仅可分配当前已注册的叶子能力；空工具列表表示仅对话。
  会话、全局记忆、委派、动态注册等管理能力不自动继承。
- Web“我的 Agent”：创建、编辑、历史、暂停/恢复、归档/恢复、独立会话；
  真实错误与409冲突保留用户输入，角色身份未解析时禁止发送，模型/引擎跟随角色配置。
- Tool/API 共用 service；CLI/TUI/Node Terminal 共用工具权限链，打开后回放真实历史。
- Agent暂不读取/提取共享语义记忆，不注入全局后台通知和团队压缩快照；
  聊天历史仍持久化，PA-02 后续补齐语义记忆的显式作用范围。
- 团队档案和成员关系可保存，循环成员关系拒绝；团队执行明确显示尚未接通。

## 配置与使用

```yaml
personal:
  data_dir: ~/.naumi/personal
```

可通过 `NAUMI_PERSONAL__DATA_DIR` 指定独立目录。一个 catalog 对应一个本地用户/安装实例；
不是公网多租户账户系统，HTTP 入口沿用已有认证。

```text
/assistants
/assistants create "山海" "根据我指定的文件整理摘要，并列出来源"
/assistants tools
/assistants open <AgentID>
/assistants pause <AgentID> <版本>
/assistants resume <AgentID> <版本>
/assistants archive <AgentID> <版本>
/assistants history <AgentID>
```

复杂配置用 `create-json` / `update-json`；Web 切换角色使用侧栏，避免在命令 Run 中切换会话。
显式用户管理命令可以管理已暂停Agent，模型自身不能通过同名工具提升权限。

可复用自然语言验收输入：

```text
请创建一个名为 Lambda-7 的 Agent，只根据我指定的文件核算预算。
给它 file_read 工具，使用快速模型。不要预先创建其他角色。
```

## 既有模块映射与文件职责

- `personal/models.py`、`store.py`：身份/事务，承接 ARC-01/ARC-05。
- `personal/service.py`、`tools.py`、`api/routes/personal.py`：统一业务接口，承接 ARC-03。
- `personal/runtime.py` 与 engine 接口：HAR-06 会话归属、现有权限与 Run 生命周期。
- `memory/session.py`：加法迁移持久身份字段，保留既有数据和生命周期规则。
- `personal/commands.py`、CLI/TUI/bridge：复用 UI-14 的共享路由。
- `frontend/web2/src/personal/`：真实目录与表单，复用既有聊天/SSE通道。
