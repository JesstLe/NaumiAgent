## 本模块合同

初始仍只有主 Agent；连接不创建或重命名 Agent。第一个 adapter 实现 Google Calendar
本人拥有的主日历；用户的平台偏好问题仍待答复，当前实现选择来自已保存的官方协议研究，
不作为用户已选择或已授权账户的事实。邮箱、其他日历、语音和设备模块保持原范围。

闭环为：桌面 OAuth → 已验证账户与最小 scope → 有界增量同步 → 手选事件转真实事项和草稿 →
人工批准确切动作版本 → 既有 Job/Run 下的有界写入 → 原事件 ID 读回 → 原结果记录。
模型可以读取已授权资料和提案，不批准自身动作。超时、503、缺回执和 404 不证明未受理，
不自动重新 POST/PATCH，也不创建新事件 ID。

## 组件与持久事实

- `connection_models.py`：严格来源、字段、日期/时区、请求及批准正文合同。
- `connection_store.py`：owner-bound SQLite、instance witness、OS bootstrap、不可变历史/请求、
  CAS、跨进程 fencing。初始化锁不跨业务回调。
- `connection_vault.py`：AES-256-GCM 密文放 SQLite，独立系统凭据 slot 只保存 32 字节随机 key。
  AAD 绑定 owner/slot/purpose/version，解决 Windows 单 credential 容量限制，并让密文与元数据
  在同一 SQLite 事务切换；不采用明文文件降级。此决策替代研究阶段的整包 token keyring 建议。
- `google_oauth.py`：固定 Google 端点、PKCE/state/nonce、维护中的 google-auth 真验签、短期
  loopback、受限证书获取。原生应用扩写权限采用显式重新授权，不称 incremental authorization。
- `google_calendar.py`：固定 `primary` 事件协议、分页/410/ETag、周期实例身份、确切写入投影和读回。
- `connections.py` / `calendar_sync.py`：实际 OAuth、凭据续期与断连、分页 staging/410、官方周期实例
  展开、确切来源、artifact/session pin、原事件→事项 outbox，以及 owner/runtime 双 witness。
- `calendar_actions.py` / `calendar_action_execution.py`：确切版本提案/人工批准、独立真实 Job/Run、
  原目标 ID 单次派发、只读对账与既有 publication/inbox。确定性协议动作不调用 LLM，
  不伪造模型 usage；领域状态不扩写或覆盖原 Job/Run 的不可变终态。
- `connection_tools.py` / `connection_commands.py` 与专用 API：共享领域 service，模型没有配置、
  连接、分享、断连或批准入口；CLI/TUI 走同一手动命令。Web 通用聊天命令不额外暴露账户管理，
  Web2 使用独立连接工作区及强认证 API。

## API 与界面合同

账户管理与人工批准只从可信手动入口进入；API 必须配置且实际通过运行时认证，不把未配置
API key 的匿名管理面视为账户批准。OAuth callback 只走短期 loopback，不匿名化普通 API。
账户正文、token、OAuth client JSON 不进入浏览器持久存储；未知请求只保存 opaque 原请求/资源 ID，
通过原 request lookup 对账。写权限升级和动作批准是两次不同的用户决定。

事件来源包含 connection/auth_epoch/event/revision/hash/occurrence，以及确切 grant ID/revision。
main 空 grant 不供其他 Agent 复用；新授权不替代已撤销的旧 grant。连接断开后，旧来源产物、
记忆、对话与派生执行也要在当前模型/工具边界失效，不能只隐藏连接按钮。

## 关键并发与来源决定

本轮连接连续性切片的原方法对照为 `2 failed, 53 deselected in 6.05s`；首次联合组为 `27 failed, 169 passed in 257.20s`（Action 夹具缺快照字段，生产字节未再修改）。补齐夹具后，service/sync/backoff/actions/action_execution/integration 六模块集中结果为 `196 passed in 288.70s (0:04:48)`，exit 0，12 个相关输入路径 `source_drift=false`；ruff 与组件导入同为 exit 0。它们是独立批次，不与此前或 Root 后续全量、前端、HTTP/浏览器结果加总。详细命令与边界见 `PA-03-actions.md`，本域原件/副本/回滚证据位于 `.naumi/transactions/pa03-read-continuity-20261105/VERIFICATION.txt`。

- 健康 connected、纯只读连接的显式 RO→RW 扩权仅在已验证 issuer/sub、email、OAuth client 均相同，且 owned 写 scope 语义覆盖原 owned.readonly 读 scope 时保留读 auth_epoch、完整 grants、镜像和 cursor；token_generation 增加，凭据使用新 slot。该过程不批准草稿，也不重发 UNKNOWN。原撤销分享、新 grant 不替代旧引用、来源撤权和 Agent 版本校验保持不变。
- 同级重授权、降权、client/email 变化、断连和已知凭据/授权异常继续 fencing：epoch 增加、grants 清空。不同 issuer/sub 直接拒绝覆盖。OAuth 原连接 revision CAS、取消状态及 account lease 在连续扩权分支同样有效；不因扩权丢失并发撤销。
- 凭据失效的即时 fencing 使用 epoch 增加使旧 grants 的 auth_epoch 失配；旧 map 可以保留为历史资料而不再授予权限。上条物理清空 grants 指非连续 OAuth 激活及 disconnect，不额外改变原失效事务的储存合同。
- 生产 Calendar 请求以 token_snapshot 绑定原 token 与其 connection/generation；刷新绑定原子提交的新 generation。旧代 401/403/429/5xx 不得被较新连接快照重新标记，也不使后来已验证的凭据失效或污染其同步状态。写入在派发前再次核对原快照；对账仍只 GET 原对象，不重写旧批准与 Job/Run 事实。

- 配置写入与原请求回执在同一事务提交；重放旧配置请求只读取当前状态，不把后来的配置覆盖回去。
- 每次 OAuth 凭据 generation 使用独立 key slot，并在 intent 先记录该 slot。重新授权、续期和
  断连共享持久 account lease；旧断连仅删除原 slot，不删除新连接的 key。远端 revoke 在本地
  原子 consume 后仅发送一次，未知结果不自动重发。
- refresh 响应中的 token/scope 不可核验、原发送 lease 结果未知时，进入 `refresh_unknown` 并
  fencing 来源；旧 generation 的失败不使后来已验证的 generation 失效。
- 同步原参数和周期实例窗口固定在 checkpoint；按本代确切 page IDs 读取，不因旧 staging 页
  积累而漏页；分页循环和容量超限不提交 cursor。429/只读 5xx 的 Retry-After、有界退避和 jitter
  持久化为下一次同步时间，不在重启或人工刷新时丢失。
- 周期 master 取消/移除使其旧实例失去可用状态；源版本、grant 和 epoch 会在实际返回/执行时重核。
- 新日历来源 artifact 使用 `authority_version=2` 元数据 marker，DB schema 仍为 1。
  旧原件 reader 因未知顶层字段拒绝新来源；派生产物经 immutable ancestry 同样阻断。
  这不是降级迁移或把旧普通资料全部禁用。当前组件缺失时也遍历祖先并拒绝连接来源。
- 动作不仅冻结显式 Calendar refs，还冻结模型本轮已读取的 artifact/memory refs 与原事项范围；
  `source_refs=[]` 不清空隐式依赖，后续 query miss 不解除旧来源授权。
- 模型 get/prepare/reconcile 在返回行动正文前发布真实文本资料、绑定持久 Session，再重核历史
  ActionRef 的原 action/revision/digest/epoch/grant 与依赖；list 仅返回 opaque 摘要，不返回正文或账号。
  人工管理读取不把正文绑到无关模型会话；缺连接组件或来源已撤销时，直接/派生资料及未来模型发送均阻断。
