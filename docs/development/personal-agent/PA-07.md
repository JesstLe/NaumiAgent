## 本轮实现范围

1. **研究记录**：综合、竞品、运营、市场领域；标题、研究问题、声明与判断。
   声明区分 `fact / estimate / unknown`；估算保留前提，判断保留执行、观察、
   暂不执行或待判断状态，以及成立前提和失效条件。
2. **来源发现与采集**：复用真实注册的 `web_search`，搜索结果与实际正文分开。
   抓取、重新观察与 PA-08 确切版本导入形成独立来源记录，保留 URL、时间、
   有效期、正文摘要、确切产物版本和来源状态，不把搜索摘要当成已经读取的正文。
3. **原文引用**：绑定来源 ID、revision、原文和出现序号。服务端按确切正文
   重新计算 Unicode 字符及 UTF-8 字节位置，不接受前端自报偏移作为证据。
   引文与复核锚点打开被引用的历史版本，不静默替换为来源最新版。
4. **机械复核**：有界 Decimal 复算比例、百分比、合计和差值；检查计算输入、
   零分母、单位、币种、时段、数量冲突、循环依赖、原文匹配和来源有效期。
   容差产生的近似差异有独立标记，不以宽容差制造严格相等结论。
5. **上游引用**：绑定研究 ID、revision、claim ID。转述保留上游未知和未独立
   核验状态，不因经过另一个 Agent 或报告就升级为独立证实。
6. **持久报告**：报告绑定已保存研究版本与确切 review digest，通过 PA-08
   ArtifactStore 形成真实版本、摘要和可重开引用；旧发布请求仍读回原发布版本。
7. **三端入口**：Tool、HTTP、CLI/TUI 与浅色 Web2 工作台共用同一研究 service。
   UI 提供草稿编辑、来源阅读/复查、检查结果、历史版本和实际报告导航。

## 复核的含义

当前 `semantic_verification` 始终为 `not_performed`；每条声明的
`independently_verified` 保持 `False`。界面固定显示“语义待核实”。

确切引文匹配只证明指定版本的正文包含该文本；数值复算只证明已声明的计算关系。
两者均不证明来源真实、引用能够支持研究结论、前提充分或建议适合用户。
`mechanically_checked` 不是语义通过，也不是独立研究者完成核实。

- notebook、source、review、read、publication 和 request 仍由各自持久记录承担
  明确职责，不新建第二套 Job/Run 执行终态。界面不以模型文字认定操作完成。
- actor、workspace、当前 Agent、来源授权和确切产物祖先在服务端重新校验；
  模型参数不提供可信调用者身份，也不替代用户入口。
- 研究形成的模型材料绑定确切来源。共享撤销或祖先授权失效后，后续读取、
  模型发送和派生产物访问重新校验，不继续展示旧标题、引文或历史正文。
- 普通 HTTP 失败、来源过期与授权拒绝分开：前者保留研究、草稿、状态和显式
  复查入口；opaque `source_unavailable` 才遮蔽整本私有材料，同时清除历史、
  检索、表单与缓存，并 fence 尚未完成的旧读取。
- 公网采集限制正文尺寸、字符数、协议、重定向及目标地址；逐跳检查解析地址，
  固定连接地址并校验原主机的 TLS 身份，不从私有来源继承网络授权。
- 具有私有资料上下文的模型不因此获得发送新检索词或 URL 的权力。显式可信
  用户入口保留手动来源操作；未来可审批的自主外发授权尚未实现。

## 原请求、并发和 UNKNOWN

- 写入绑定稳定 `request_id`、不可变 payload、actor/workspace 和预期 revision；
  同 ID 不同内容冲突，CAS 并发只允许一个胜者，不覆盖另一窗口的新版本。
- 外部采集/检索在发送前持久化操作阶段；已经发送但没有可信结果时保留待核对，
  不因超时、取消或重启自动重复外部调用。
- Web localStorage 仅保存操作、原请求 ID 与 opaque 目标；私有正文和完整 payload
  不落入该恢复槽。当前挂载内的显式重试复用原 payload/ID；重挂载后只 GET 对账。
- 页面隐藏、断连或卸载不取消已经提交的服务写入；旧身份的异步响应不回填新身份。
  CAS 冲突保留草稿，载入新版本由用户明确选择。
- 已受理但来源不可用的结果仍确认原收据，不把确定的受理结果伪装成 UNKNOWN，
  也不恢复已失效的敏感材料。
- 研究目录按 keyset 跨身份扫描，不在第 1000 条记录处静默截断；历史列表和原请求
  回放逐项绑定返回的确切研究版本。直接读取历史来源也保留该版本的真实材料和凭据。
- 检查期间和报告形成期间若来源改变，原结果不绑定到新来源、不形成虚假通过。
  同主体数量冲突会沿计算依赖传播，上游未知和问题不会在多层计算后消失。

## 使用入口与调用格式

Web2 的研究入口可管理记录、添加来源、引用原文、保存、检查、查看历史和导出。
模型使用 `personal_research`，用户命令使用相同执行适配层；14 类操作包括
`context / list / get / source / history / request` 与下面八类写入操作。

```text
/research context
/research list --limit 20
/research get <研究ID> --revision <版本>
/research source <来源ID> --revision <版本>
/research history <研究ID> --limit 20
/research request <原request_id>
/research <create|revise|search|capture|import|recheck|review|publish>-json '<完整JSON>'
```

新建格式示例（示例不是运行收据；每次新的意图使用新的稳定请求 ID）：

```json
{
  "operation": "create",
  "request_id": "7f13f681aa544d58aa21b18bb3b052c3",
  "title": "本月收入研究",
  "question": "原始材料中的收入、成本与比例是否一致？",
  "domain": "general"
}
```

`*-json` 命令省略对象内的 `operation`，因为子命令已经指定操作。
