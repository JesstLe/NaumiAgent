# PA-06 专员互询界面

## 实现边界

本模块延续已有的协作工作台，不创建预设专员、不改变档案能力，也不把打开对话视为发送方已读。目录中的真实专员由用户选择；业务执行、版本检查、派送去重及运行身份由后端负责。

### 显式互询授权

- 协作表单保存 `{agent_id, agent_version, tool_names}` 快照，最多 128 位专员。
- 默认只选真实工具目录中 `read_only=true` 的能力，以及档案已分配的 `personal_message`；写入能力必须逐项勾选。
- 工具元数据缺失不获得默认写入权限。普通无互询协作仍可提交，已选择互询范围的协作须先取得有效工具元数据。
- 版本变化不会自动扩大权限。用户更新授权版本时仅保留仍存在的原工具子集。

### 手动消息

- 发送方须已拥有 `personal_message`。接收方不要求具备发送能力。
- 发送包含精确双方版本、显式正文与共享上下文；允许对端继续询问发送方需要明确选择。
- 首次提交固定完整请求、来源会话及幂等 ID。响应不确定时锁定原表单并原样重试，不自动换 ID，也不让新授权覆盖旧请求。
- 工作流与手动消息使用独立草稿及 reset key；切换页面和成功提交另一份草稿都不覆盖未提交内容。

### 双方对话与收件回执

- 列表通过真实 HTTP 接口加载；展开后独立读取完整正文，拒绝截断或错误身份的完整响应。
- 显示实际双方版本、原始请求、共享上下文、完整回应与交付回执。
- 两端执行链接仅在相应 Run ID 已存在时出现，并打开各自真实会话。
- 用户点击“确认收到”才提交 `expected_response_sha256`。用户回执和专员回执使用不同标签。
- 已核实的确认事实不会被旧 GET/轮询快照回退；同一消息的身份、Run 或结果摘要冲突会保留原结果并明确报错。
- UNKNOWN、受阻、取消、错误和超时各自保留，不从根任务或消息文本推断完成。
- 活跃消息与执行使用可清理的定时刷新；组件关闭后停止刷新。

### 专员交互归属

授权和提问事件须绑定存在的根步骤。对端事件还须匹配 `peer_message_id`、真实接收会话及 `peer_sessions.step_id`；摘要中存在同一消息时同时核对步骤。提问还检查根步骤正在执行和对端正在处理。界面展示实际执行人的 `actor_name`。
