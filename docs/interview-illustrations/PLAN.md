# 教材逐章教学配图方案

更新日期：2026-09-11。

## 范围与状态

为 `docs/interview` 中现有 27 份教材文档各制作一张教学图：总纲、14 个核心模块、10 个延伸章节、阅读导航、离线实验。不是只给十四章配图，也不是为每个小节各生成一张。

当前状态：27 张选定图片已使用内置生图能力生成、逐张检查并插入本地章节，原教材正文完整保留。工具不暴露具体模型身份，不标注为 image2.5。`prompts.json` 保留首版提示词，`manifest.json` 保存最终选中版本的实际提示词、路径与读图说明，`verification.json` 保存完整性检查结果。飞书图片尚未插入：浏览器扩展文件上传返回 Not allowed，系统文件选择器也未完成上传；需解决上传权限后继续原位插图。不得把本地完成写成飞书同步完成。

## 统一生成提示词

每张最终提示词由以下公共要求与对应章节的专属要求组成，生成时保存完整提示词及工具实际返回的模型信息；未返回模型标识时记录“未暴露”，不得猜测。

> 用途：面向有编程基础、刚学习 AI Agent 的中文教材教学图。使用 scientific-educational / infographic-diagram 风格，生成一张清晰的横向教学信息图。白色背景、深色大字，蓝色表示普通执行，绿色表示已核验结果，橙色表示等待或边界，红色仅表示拒绝或故障；同时配文字和形状，不能只依赖颜色表达含义。层级清晰，适合嵌入飞书正文，中文必须准确可读。优先展示机制、因果关系和一个反例，不要做装饰封面、机器人海报、品牌宣传或满屏术语。短标签优先，箭头方向明确；箭头只连接专属要求明确说明的节点。标题使用本章图题。教学示意必须标明“教学示意”，不能暗示图中所有增强能力已在 NaumiAgent 实现或通过生产验证。不要生成排名、虚构跑分、招聘保证或销售文案。

## 逐章专属要求

下表中的编号与原章节一致；25 对应 `labs/README.md`，nav 对应教材 `README.md`。

| 编号 | 图题 | 必须画出的关系 | 关键校验与图下注释要点 |
| --- | --- | --- | --- |
| 00 | 从最小闭环到工程化 Agent | 中心为目标→上下文与模型决策→行动→观察→下一轮决策；核验满足目标才结束。外围分“运行治理”“按需接入”“进阶协作与演进”，归入十四模块。 | 权限位于行动前；十四模块是教学分类，不是每个 Agent 的必选独立子系统。 |
| 01 | 愿望、验收与授权是三件事 | 用户“整理周报”进入目标对象、成功标准、约束、状态四格；草稿经内容与来源核验交付。发送邮件走独立授权门，不在默认草稿链内。 | 不把生成草稿画成邮件已送达；取消不自动撤销已发生的副作用。 |
| 02 | 一次任务如何推进与停下来 | 建立运行→组装上下文→模型决策→动作检查→工具→观察，观察反馈下一轮；另画等待用户、结果未知待对账、完成核验出口。 | 标注概念流程非源码统一枚举；业务状态与运行状态用两个泳道区分。 |
| 03 | 模型档位不等于智能路由 | tier 配置→具体模型→Provider 与协议适配→能力检查→实际调用→记录身份和用量；失败分支进入兼容性检查后再降级或暂停。 | fast/capable 可以映射同一模型；动态风险路由用虚线标“可选设计”；计账不等于调用前额度预留。 |
| 04 | 一个上下文窗口该装什么 | 多源输入经过相关性选择；关键约束、当前状态、近期消息进入窗口；长工具输出放工件，窗口保留引用；历史压缩为摘要。 | 摘要有损，来源和授权不能被摘要升级；以 32k 总量、4k 输出、2k 余量、26k 输入标“计算示例”。 |
| 05 | 四种记忆，四种职责 | 会话状态、长期偏好、知识资料、任务与授权账本四个独立容器，分别连接恢复、个性化、带引用检索、按 ID 对账。 | 语义相似不等于事实正确；账本不可用相似召回来替代；资料访问先过滤权限。 |
| 06 | 计划可变，执行事实要核对 | 上层 Plan：收集 A 与 B→比较→报告，其中 A、B 并行。下层 Todo 记录 pending/in_progress/blocked/completed，并连接独立产物核验。 | 不画不存在的 Todo cancelled；全部 completed 仍可能缺文件；对账不等于全目标验收。 |
| 07 | 从工具调用到业务结果 | 模型 call_id/name/arguments→JSON 与字段检查→业务授权→执行→同 call_id 返回结果→业务核验；错误分支区分拒绝、失败、结果未知。 | 参数合法不等于业务合法；202 已接受不等于后台完成；不承诺所有工具都有幂等键。 |
| 08 | 权限应在真正执行时生效 | 身份→动作/资源范围→短期批准→执行时复核→受限工具；父 Agent 委派子任务只传递权限子集；网页恶意指令无法穿过授权边界。 | 认证、授权、沙箱分层，不互相替代；图中不出现密钥；批准过期或撤销应拒绝。 |
| 09 | 为什么超时后不能直接重试 | 两条时间线：A 持旧 epoch，租约过期，B 获新 epoch；A 回来提交存储写被 Fence 拒绝。外部发送另一路在超时后查询回执/对账。 | 明确 Fence 不能撤销已经发出的邮件，不保证外部 exactly-once；心跳只说明活跃不证明进度。 |
| 10 | 运行支撑与评测支撑分工 | 左侧运行 Harness 管上下文、工具、权限、停止并产出轨迹与工件；右侧 evaluation harness 固定任务/环境/预算与评分器，对基线和候选分别评分。 | Trace 是发生记录，不是正确性结论；以环境断言为证据，不把模型自报当验收。 |
| 11 | MCP 连接能力，Skill 提供方法 | Host 内包含模型和 Client，Client 连接外部 Server；initialize→list_tools→call_tool→result。Skill 的索引→正文→可选资源进入任务方法，再使用获授权工具。 | Skill 不直接授予 MCP 权限；SKILL.md 可无脚本；本项目 stdio 工具桥与远程 HTTP 可选协议概念分区。 |
| 12 | 浏览器操作是观察与核验循环 | 观察页面→定位目标→检查权限→点击或输入→重新观察；下载后核验文件、月份、数量；登录失效转等待人工，完成后继续。 | 点击不等于业务成功；Browser 与原生桌面 Computer Use 分区；不画绕过验证码流程。 |
| 13 | 子 Agent 与 Worker 不是同一种角色 | 父 Agent 发出三个独立证据收集合同，子 Agent 返回证据供汇总；下方独立资源层由队列、容量、Worker 承载任务，两层以分配线连接。 | 不画固定一对一映射；有依赖任务不能强行并行；多角色或多进程不等于已验证跨机集群。 |
| 14 | 改进候选必须允许被拒绝 | 失败样本→不可执行候选→隔离实验→固定基线比较→审批绑定版本→有限发布→观察；不合格回到拒绝/修改，退化回滚已知版本。 | 生成、评测、批准、发布用权限边界分开；签名不证明质量；不画自动修改生产的捷径。 |
| 15 | 比较 Agent，先对齐层次 | 模型、SDK、编排 Runtime、Harness、最终产品五层责任卡；同一“目标—行动—反馈”贯穿，旁列应用方仍需承担的工具、权限、数据与部署责任。 | 不做厂商品牌能力排行榜，不画所有产品严格只属于一层；本图是比较方法而非新性能结论。 |
| 16 | 一段项目介绍背后的证据链 | 背景与目标→个人负责范围→关键取舍→代码与测试→结果与局限；旁边标 30 秒概述、90 秒展开、5 分钟沿任务深入。 | 阅读、复现、独立改造三个贡献层次分开，不能把全项目归为学习者原创。 |
| 17 | 用一个任务读懂 Agent 术语 | 用户目标送入 Runtime；Context 供模型决策；Tool 改变环境；Memory/RAG 提供资料；Ledger 保存精确状态；Trace 记录，Eval 核验；Skill/MCP 放在方法与连接旁注。 | 只画各自职责，不能把 Tool、MCP、Skill 画成同义替换；不把日志等同评测。 |
| 18 | 一项结论需要哪种证据 | “源码实现”“单元测试”“本地离线运行”“真实模型运行”“生产验证”五类证据卡，指向各自能支持的结论；未运行和失败单列状态。 | 这是证据范围图，不是项目全部通过的阶梯；不得生成全绿徽章或虚构通过数量。 |
| 19 | 从编程基础到六项学习成果 | 基础自测→离线复现→真实任务→独立改造→实验复盘→项目表达；成果卡为环境记录、任务演示、源码走读、个人补丁、实验报告、项目介绍。 | 不许画保录用或“全岗位覆盖”；应用开发为主，训练算法与高级平台能力属于另需补足的方向。 |
| 20 | 周报草稿助手的学习主线 | S0 环境→S1 离线机制→S2 产品入口→S3 真实模型任务→S4 源码映射→S5 个人改造→S6 面试交付；数据→草稿→核验作为具体产物流。 | 草稿保留阻塞事项，不发送；离线已提供与读者需自行执行的 live 实践用不同状态标识。 |
| 21 | 换业务，不换工程检查方法 | 中央统一合同：输入、权限、结果、失败；向知识问答、工单查询、发票下载三列展开，各列给来源核验、身份/版本核验、文件范围核验。 | 标“迁移实验设计”；不能画三个现成生产集成；受限资料应在进入模型前过滤。 |
| 22 | 怎样形成自己的代码贡献 | 具体失败→可检验需求→反例测试→最小范围补丁→回归与真实场景→提交证据；用“草稿缺 UPD-003”贯穿，展示缺失/重复/未知来源三个输出。 | 源 ID 出现不等于语义正确；不把更名、改皮肤画成完整自研。 |
| 23 | 公平实验与诚实结论 | 相同输入、环境、预算和评分器分别进入基线/候选；汇总成功、失败、超时、成本与安全；反例回到问题定义，报告标样本量和边界。 | 不虚构提升数字，不删除失败分母，不把教学断言通过率当模型任务成功率。 |
| 24 | 面试练习是可追问的展示 | 45 分钟时间轴：5 分钟项目、10 分钟概念、10 分钟源码、10 分钟改造调试、10 分钟设计复盘；下方背景→个人贡献→证据→边界。 | 总时长必须 45 分钟；明确为训练安排，不是某大厂真实面试流程。 |
| 25 | 五个实验都通过，不等于五项业务都成功 | 五行场景：complete、pending、stale、missing-artifact、tampered-artifact；两列分别为“教学断言符合预期”和“业务目标达成”。第一列五个是，第二列只有 complete 为是。 | 场景差别用状态/文件/内容小图说明；标“零模型请求的离线机制实验”；不用绿色实验退出码冒充业务完成。 |
| nav | 一本教材怎样变成自己的项目能力 | 学习定位→环境与离线实验→十四模块与源码→场景迁移→个人改造→评测复盘→面试自测；自测暴露缺口后回到相应模块形成学习闭环。 | 阅读导航不是生产架构图；成果是能复现、能解释、能验证，不是背熟术语。 |

## 保存、插入与验收

1. 一章一张独立图片；先检查第一张的字体、密度与风格，再沿相同视觉规范逐张制作。每张单独调用生成工具，不用一张拼图冒充全书配图。
2. 图片保存到 `docs/interview/assets/illustrations/`，建议文件名为 `00-overview-v1.png` 至对应章节名及 `nav-learning-map-v1.png`。已有版本不覆盖；实际扩展名以输出为准。
3. 每张检查中文错字、箭头、分支、状态名和事实边界；复杂图需要针对局部修订后再检查。不通过的图不插入正文。
4. 图片插入相应章节的引入之后、源码或深入讲解之前，配替代文本、简短读图说明与必要的边界说明。图不能替代原来的详细讲解。
5. 飞书在原有章节原位插入，不重新导入而产生整套重复章节；保持原有成员可见权限。检查图片可打开、正文未被覆盖、章节标题与图片一致，并确认已保存到云端。
6. 交付记录列出每张实际文件、完整提示词、生成接口及实际可知的模型身份、人工视觉核查结果、飞书插入状态；未完成项明确保持未完成。
